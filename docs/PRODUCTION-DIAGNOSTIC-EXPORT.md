# Выгрузка одного продового звонка или тренировки для локальной диагностики

Экспорт только читает БД и локальное хранилище записей. Он не пересчитывает отчёт и не меняет сессию. Основной вариант — защищённый HTTP-запрос с локального компьютера; консольный экспорт на сервере оставлен как запасной.

## Прямой запрос с локального компьютера

Один раз после обновления кода добавьте **на проде** в `.env` отдельный секрет `DIAGNOSTIC_EXPORT_TOKEN` (не используйте `AUTH_TOKEN_SECRET`):

```bash
openssl rand -hex 32
```

Скопируйте полученные 64 символа в `DIAGNOSTIC_EXPORT_TOKEN=...` и перезапустите контейнер приложения, чтобы он получил новую переменную. Для развёртывания нового кода понадобится пересборка контейнера. Токен не вводите в чат или URL.

**Локально** в `.env` укажите `PROD_DIAGNOSTIC_BASE_URL=https://адрес-приложения` и `PROD_DIAGNOSTIC_TOKEN=...` (тот же секрет). Затем из каталога проекта:

```bash
npx tsx src/scripts/fetchDiagnosticCase.ts trainer cmv... --audio
npx tsx src/scripts/fetchDiagnosticCase.ts call 199 --audio
```

Команда печатает путь к скачанному `.json.gz` в закрытом временном каталоге системы. Без `--audio` передаются только текстовые данные, оценки и метаданные. Для большой тренировки `--audio --turn 4` скачает аудио только четвёртой реплики менеджера. Достаточно прислать ID или ссылку на кейс: при наличии локального токена и сетевого доступа пакет можно запросить без входа на сервер. Если доступ извне к адресу приложения или токен отсутствуют, прямой запрос работать не будет.

Ручка: `GET /api/internal/diagnostics/{trainer|call}/{id}`; опциональные параметры — `audio=1` и `turn=N`. Авторизация — заголовок `Authorization: Bearer <DIAGNOSTIC_EXPORT_TOKEN>`. При пустом или слишком коротком токене ручка отключена. Используйте только HTTPS. Ответ `.json.gz`, `Cache-Control: no-store`; токен никогда не передаётся в URL. Доступ даёт возможность читать реальные диалоги и записи, поэтому секрет надо хранить как продовый ключ и при утечке немедленно заменить на обоих концах.

## Запасной консольный экспорт на сервере

Используйте его, если прямого сетевого доступа нет. Из `/srv/salesboost`:


```bash
./scripts/export-prod-diagnostic.sh trainer cmv... --audio
./scripts/export-prod-diagnostic.sh call 199 --audio
```

Для звонка допустим как числовой ID из `/audits?callId=199`, так и UUID звонка. Для тренировки нужен ID из ссылки `trainingId=...`. Передавайте только ID, не полную ссылку.

`--audio` добавляет сохранённое аудио реплик менеджера в тренировке или локальную запись звонка. Без флага выгружаются транскрипт, контекст и оценка, но не аудио. Если пакет тренировки получается большим, можно добавить `--turn 4`: в нём останется аудио только четвёртой реплики общего транскрипта (нумерация с 1), а текст всех реплик сохранится. У звонка запись нельзя ограничить одной репликой.

Готовый файл имеет формат `.json.gz` и сохраняется в `/srv/backups/diagnostics/`; путь команда напечатает после успешной проверки архива. Файл создаётся с правами текущего пользователя и `umask 077`. Чтобы сохранить в другом каталоге, задайте `DIAGNOSTIC_OUTPUT_DIR` перед командой. Например:

```bash
DIAGNOSTIC_OUTPUT_DIR=/srv/my-diagnostics ./scripts/export-prod-diagnostic.sh trainer cmv... --audio
```

Передайте полученный файл по защищённому каналу или приложите его к задаче. Это диагностические данные с реальными репликами и, при `--audio`, голосами людей. Не кладите файл в Git, публичный каталог сайта или общий чат. Структурные поля с токенами, паролями, телефонами, email и IP скрываются, но персональные сведения могут оставаться в самом тексте и аудио.

Если локальной записи звонка нет, экспорт всё равно создаст пакет без аудио и сообщит об этом в консоли. Экспорт не скачивает запись заново из Voximplant. Для старых тренировок в пакете могут отсутствовать данные о том, какой сервис сформировал конкретный ответ: раньше этот маршрут не сохранялся для каждой реплики. Аудио и текст распознавания помогут проверить STT; оставшиеся вопросы можно уточнить по логам продового контейнера.
