# Внутренняя аналитика v3

Реализация по PDF «Salsa — ТЗ: внутренняя аналитика и события v3» от 11.11.2026.
Страница: `/internal-analytics?tab=activity`. Формулы и порядок блоков соответствуют разделам 3–6 PDF. Ссылка на внешний макет из PDF недоступна из среды разработки; визуальная сверка с ним не выполнена.

## Изменения

- Фильтры компании, точки и периода сохраняются в URL: `tab=activity&company=<id>&branch=<id>&period=30`. Смена компании сбрасывает точку.
- Пять KPI, активные люди по дням/неделям, таблица компаний/точек, руководители и сотрудники, тренажёр, звонки, ценность продукта и разделы. У показателей есть пояснения; отсутствие знаменателя или данных для оценки возвращается как `null` и отображается «—».
- Активность — действия человека и начало тренировки сотрудника, по уникальному `accountId`. Системные звонки не добавляют активных людей. Тренировки администраторов без роли сотрудника исключены.
- Тестовые и удалённые компании, удалённые точки и аккаунты нашей команды исключены из активности. Переключатель «Тестовая» в форме компании доступен только суперадминистратору.
- North Star: первые 20 завершённых оценённых звонков пары «точка + скрипт» — база; минимум 10 последующих звонков в окне 30 дней; обрывы исключены. Скрипты внутри точки взвешены по числу звонков окна, точки имеют равный вес.
- Повторные действия агрегируются в SQLite. Для звонков читаются первые 20 оценок пары и нужный временной диапазон. Ответ кэшируется на 5 минут с учётом фильтров; одновременные одинаковые запросы объединяются.
- Единый список 24 событий, стандартные свойства и нейтральные роли. Системность определяется по имени события на сервере. Открытие отчёта не создаёт события раскрытия блоков; `score_viewed` удалён.
- В Amplitude используются время факта, ключ дедупликации, группы `company`/`branch`, названия и `identify` при изменении контекста. Команда и тестовые компании наружу не отправляются. События сохраняются в собственной базе независимо от Amplitude.
- Ошибки API и фоновых задач направляются через `reportError`; у запросов и фронта есть теги компании, точки и роли. При SIGTERM/SIGINT закрывается HTTP-сервер и ожидается отправка событий Amplitude и Sentry.

## Модули

- `src/analytics/activity/`: источники, область, люди, тренажёр, звонки, North Star, таблица и сборка ответа. Prisma и старые имена сущностей внутри этого каталога находятся в `sources.ts`.
- `src/analytics/productAnalytics.ts`: перечень событий, проверка входных свойств, контекст, запись и отправка.
- `src/analytics/callEvents.ts`, `trainingEvents.ts`: факты жизненного цикла звонков и тренировок.
- `admin-frontend/src/pages/internal-analytics/ui/activity/`: отдельный компонент каждого блока.
- `admin-frontend/src/components/ui/`: локальные примитивы Card, Badge, Select, ToggleGroup, Table, Tooltip и Chart; графики — Recharts.

## API

`GET /api/admin/internal-analytics/activity?period=7|30|90&companyId=<id>&branchId=<id>`

Доступ только `platform_superadmin`; компания необязательна, точка выбирается вместе с компанией. Некорректный период или чужая точка — 400; отсутствующая, тестовая или удалённая компания — 404. Списки фильтров приходят вместе с данными. Контракт — `src/analytics/activity/types.ts`.

## Импорт сотрудников

Добавлен отдельно по уточнению пользователя. В разделе «Сотрудники» кнопка «Импорт сотрудников» открывает загрузку CSV UTF-8 с предварительной проверкой. До 200 строк, разделители `,`, `;` и табуляция, поддерживаются кавычки и BOM.

Колонки:

| Колонка | Правило |
| --- | --- |
| `email` | Обязательна, уникальный адрес аккаунта |
| `fullName` | Обязательна, 2–160 символов |
| `password` | Обязательна, 8–128 символов; пробелы сохраняются |
| `branchId` | ID точки; можно заменить выбором одной точки для всего файла |
| `phone` | Необязательна; проверяется уникальность номера в точке |

Компания выбирается перед импортом. Сервер разрешает только точки этой компании, доступные текущей роли руководителя. Создаётся только роль сотрудника; CSV не может назначить административные права. Существующие аккаунты не перезаписываются. Любая ошибка отменяет весь файл.

Пароли не входят в ответ предварительной проверки и в события, хешируются асинхронным scrypt. Запись выполняется одной транзакцией с повторной проверкой ограничений. После успешной записи создаётся один факт `employees_imported` с количеством, источником `csv` и идентификатором импорта.

- `POST /api/admin/employees/import/preview`
- `POST /api/admin/employees/import`

Тело обоих запросов: `{ companyId, rows: [{ email, fullName, branchId, password, phone? }] }`.

## Запуск

Перед запуском нового кода применить миграции и сгенерировать Prisma Client:

```sh
npx prisma migrate deploy
npx prisma generate
npm run build
```

Миграция `20261111120000_internal_activity_v3` добавляет `isTest`, `initiatedBy`, переименовывает колонки событий с сохранением истории, переносит имена событий/ролей/целей, восстанавливает разделы старых просмотров и удаляет дубли `score_viewed` и автоматических показов рекомендаций. В рабочую БД при разработке миграция не применялась; проверка выполнена на временных данных.

На проде оставить `AMPLITUDE_API_KEY`. Для непродуктивных окружений используется **только** `AMPLITUDE_DEV_API_KEY` отдельного проекта; при отсутствии ключа события остаются в базе. `SENTRY_ENVIRONMENT=production` выбирает продуктивный проект, другие значения — отдельный тестовый ключ. Задать `SENTRY_RELEASE` для свойства `app_release`.

После миграции отметить фактические тестовые компании переключателем «Тестовая»: миграция не угадывает их по названию.

## Внешняя настройка

Изменения внешних аккаунтов не выполнялись: создание отдельного проекта Amplitude, его ключ, русские описания/скрытие старых событий в плане Amplitude и правила оповещения Sentry настраиваются в этих сервисах. Дашборды Amplitude в эту задачу не входят, согласно PDF. Дополнительный внешний мониторинг `/health` не подключался.

## Проверка

Профильные тесты покрывают системные звонки без активности человека, исключение администраторов/теста/команды, 19/20 базовых звонков и минимум окна, обрывы, несколько скриптов и точек, московские границы дня, недельную уникальность, дельты, состояния тренировок, фильтры, реальные SQLite-запросы, контекст и отправку событий, импорт CSV, права, пароли и отсутствие частичной записи. Миграция отдельно проверена на старом формате событий.

Общая сборка проходит. В общем наборе воспроизводятся четыре ранее существовавших падения в `hypothesis2Interruption.test.ts` и `hypothesis2ProductionParity.test.ts`; те же падения проверены в отдельной копии исходного `HEAD`. Проверка интерфейса в браузере не выполнена.
