# Основная телефония планов: OpenAI Realtime + ElevenLabs + Voximplant

Ручной запуск плана и планировщик используют `prepareCallPlanTelephony`.
По умолчанию выбран `CALL_PLAN_TELEPHONY_PROVIDER=openai_realtime`.
Модель, паузы, ASR и голосовые параметры — те же `OPENAI_REALTIME_*` и настройки ElevenLabs, что у проверенной гипотезы 2.
OpenAI выдаёт текст, ElevenLabs озвучивает голосом выбранного профиля, Voximplant передаёт звук и записывает обе стороны в стерео.

## Развёртывание

1. Нужны `OPENAI_REALTIME_API_KEY`, `ELEVENLABS_API_KEY`, настройки Voximplant и публичные `VOICE_DIALOG_BASE_URL` / `PUBLIC_BASE_URL`.
2. `npm run deploy:openai-realtime` проверяет отдельные сценарий и правило, ничего не меняя.
3. `npm run deploy:openai-realtime -- --apply` создаёт/обновляет только `voice_openai_realtime` и `voice_openai_realtime_rule`. Старые Agent- и тестовые сценарии не меняются. У правила намеренно нечисловой шаблон: входящая маршрутизация не перехватывается.
4. Развернуть/перезапустить backend с маршрутами `/voice/openai-realtime` и `/webhooks/vox-openai-realtime`. Сам deploy-скрипт не звонит и не запускает планы.
5. Выполнить один контролируемый звонок и проверить карточку плана, запись, исходный/повторный транскрипт и отчёт. Не запускать массовый план для первой проверки.

На 29.10.2026 отдельный сценарий загружен через API и сверен с локальным файлом:
`scenario_id=3755373`, `rule_id=9621279`. Загрузка не запускает звонки.
Автотесты проверяют обработку с подменёнными API/БД; реальный звонок со скачиванием записи и генерацией отчёта остаётся отдельной проверкой после развёртывания backend.

## Обработка

- Провайдер и профиль фиксируются до набора; записи `VoiceCallSession` и `CallPlanCall` создаются до `StartScenarios`, чтобы быстрый webhook не создал непривязанный звонок.
- Состояние Realtime сохраняется раз в секунду и при завершении в приватный `storage/voice-realtime/<callId>.json`. Это исходный транскрипт, тайминги, инструменты и usage, без API-ключей. Каталог должен быть на постоянном диске и не публиковаться веб-сервером.
- Lifecycle webhook защищён отдельным случайным токеном на звонок; на диске хранится только SHA-256. Тестовые endpoints не выдают производственные сессии.
- Терминальное событие проходит через обычные `processVoxWebhookPayload` и `finalizeVoiceCallSession`: статусы, IVR, запись из Voximplant в существующее хранилище, повторная транскрипция, атрибуция менеджера, чек-лист, условия сценария и полный отчёт.
- Одновременные повторные финальные события объединяются; готовый отчёт не сбрасывается повторной доставкой. Занято/недозвон не оцениваются как разговор с сотрудником.
- После `end_call` команда завершения отправляется по подтверждению окончания воспроизведения, без ожидания ответного прощания.
- Тестовый и плановый звонки используют общую фабрику Realtime-сессии, одинаковые три попытки подготовки соединения и общий выбор streaming-голоса (включая резервный голос до сборки промпта).
- Поздняя ASR-проверка перебивания привязана к конкретной дорожке: если Voximplant уже подтвердил её окончание, произнесённый ответ не удаляется из контекста. Проверено регрессией по гонке из звонка `e8442a74-5a84-4c00-8366-5abec43cf3ea`.
- `usage` OpenAI сохраняется для диагностики. Цену прямого OpenAI нельзя подменять тарифом ProxyAPI или стоимостью ElevenLabs Agent; эти данные не являются подтверждённым денежным расходом.

## Откат

Установить `CALL_PLAN_TELEPHONY_PROVIDER=elevenlabs_agent` и применить конфигурацию backend. Новые ручные и автоматические звонки пойдут через сохранённый `realtime_pure` / ElevenLabs Agent. Не требуется удалять новый сценарий или менять планы. Не перезапускайте процесс посреди звонка: конфигурация фиксируется на запуск, но остановка самого процесса разрывает его WebSocket.

Тестовая страница `/testing` остаётся изолированной: её звонки по-прежнему не создают плановую оценку или запись основного процесса.
