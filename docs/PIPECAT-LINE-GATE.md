# Защита телефонной линии · semantic-14

Основной semantic-профиль и гипотеза получили шлюз линии перед смысловым контроллером (`apps/pipecat-hypothesis/line_gate.py`). Реестр вопросов, подтверждение визита и завершение после playback ACK сохраняются.

Semantic-14: [защита от ложного повтора, реакции слушания и стиль плана](PIPECAT-CALL-2141ac4c.md).

- До подтверждения сотрудника запрещены приветствия, вопросы, native TTS и бэкченнелы. Блокировка действует в контроллере, сериализаторе аудио и Voximplant. Фон играет с момента соединения, включая IVR и удержание, независимо от блокировки голоса.
- Явные приветствия, автоответчик и ожидание определяются локально. Неоднозначная реплика и меню проверяются через Decisions (таймаут 4 секунды). Ошибка/неуверенность оставляют линию в молчаливом ожидании.
- Терминальная голосовая почта/ассистент завершают звонок без прощания. Ассистент, пытающийся соединить, оставляет звонок на ожидании. Без человеческого разговора исход — `no_answer`/`busy`; прежний фильтр пригодности отчёта сохраняется.
- В IVR разрешена одна явно предложенная кнопка после окончания списка. Выбор учитывает цель текущего плана: нужный отдел, затем общий оператор. Неизвестные варианты не набираются. Задержка после меню — 1,2 секунды с проверкой новой речи/актуальности реплики; минимум 2 секунды между командами, максимум 6 нажатий. Повтор ID команды не повторяет набор.
- Путь сохраняется после ACK Voximplant/lifecycle. ACK означает принятие вызова `sendDigits`, а не доказанный приём цифры удалённым IVR.
- Шум и короткие ответы не переводят подтверждённого человека обратно в IVR. Явное меню с кнопками и прямой перевод/просьба подождать закрывают канал. После возвращения сотрудника сохраняются имя, факты и вопросы; после приветствия нового сотрудника восстанавливается незавершённый вопрос.
- Реплики меню остаются в диагностике, но исключаются из пользовательских реплик бизнес-памяти. Ответ сотрудника с последующей просьбой подождать сохраняет факты без озвучивания продолжения на удержании.
- `PIPECAT_LINE_WAIT_SECONDS`: по умолчанию 180, диапазон 30–600. После таймаута ожидания — молчаливое завершение. Подтверждение человека снимает таймер, перевод запускает новый.

`ivrDetected`, подтверждённый `ivrPath`, состояние и причина остановки передаются в production snapshot и backend. Путь сохраняется в `VoiceCallSession.ivrPathJson`. События `line_*` доступны по обычному `pc-…`. Разговор перед последующим переводом на почту сохраняется как разговор.

## Проверка без PSTN

Синтетические тексты через настоящий Decisions API:

```sh
docker exec salesboost-pipecat-pipecat-1 python probe_line_gate.py
```

Сценарий IVR → сотрудник → перевод → продолжение → прощание с настоящими Realtime/Decisions/ElevenLabs, текстовым входом и имитацией телефонных ACK:

```sh
docker exec salesboost-pipecat-pipecat-1 python probe_controller.py --provider openai --dialogue-mode semantic --scenario semantic_ivr_transfer
```

Python-тесты проверяют ошибки/неуверенность, отмену устаревших результатов, таймаут, перевод, факты, блокировку аудио и DTMF ACK. Node VM проверяет оба Vox-сценария и набор. Backend-тесты проверяют IVR в snapshot, БД и финальном webhook, прежние фильтры автоматических ответов.

Эти проверки не измеряют живое ASR и прохождение DTMF через телефонную сеть: нужен контрольный звонок на реальную IVR. Классификация вероятностная: короткое «Здравствуйте» может быть принято за сотрудника; последующее явное меню снова блокирует аудио.

В semantic-13 короткое приветствие, включая английскую транскрипцию русского «алло», сразу запускает подготовленное вступление без Decisions/генерации. Блокировка на явных записях/меню сохраняется. Старт native-ответа не считается отправкой вступления. Недоговорённый вопрос о наличии имеет стабильный `plan:availability` ID и может быть восстановлен через общий механизм однократного возобновления прерванных вопросов. Разбор звонка: [PIPECAT-CALL-bd989d6f.md](PIPECAT-CALL-bd989d6f.md).
