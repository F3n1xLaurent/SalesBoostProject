Исправления после звонка `pc-b6cc2d7e-a57b-44eb-9540-2bca0e4d1aa3`, 12 ноября 2026.

Изолированный сервис гипотезы, runtimeRevision `pipecat-turns-1`. Общие изменения действуют для Realtime 2.1 и Mini.

- `response.create` сериализуется: следующий запрос ждёт настоящего `response.done`, отмена до `response.created` ждёт ID. Повторная отмена не отправляется. Отказ API удаляет соответствующий запрос из очереди диагностики по client event_id.
- Поздняя STT старой реплики сохраняется как доказательство, но не начинает ответ и перебивание во время новой реплики. Короткое «Давайте» при уточнении времени получает окно продолжения 700 мс после финальной STT; новая речь отменяет уточнение. Это отдельная защита незаконченного фрагмента, не настройка Silero или Smart Turn.
- После commit очищается pre-roll уже отправленного аудио независимо от экспериментального trimIdleAudio. При перебивании повторяется только новый незакоммиченный звук.
- День и время визита сохраняются атомарно через prepare_end_call. Консервативные кандидаты берутся только из явных предложений сотрудника с исходными цитатами. Альтернативы и отрицания не превращаются в подтверждённую договорённость; более новое предложение защищено от старой цитаты. Модель видит кандидаты и конкретную причину отказа. Допустимые поля и причины закрытия перечислены enum в схеме инструментов.
- Литеральные маркеры тишины и ограниченный набор служебных фраз отфильтровываются перед TTS; в диагностике отдельно сохраняются сгенерированный и отправленный на озвучку текст. Возможное закрытие после согласования визита удерживается до решения инструмента. Подтверждение визита и прощание произносит backend; hangup ждёт подтверждения воспроизведения нужного ответа.
- Для первого пустого ответа на простое приветствие предусмотрен один повтор генерации; для приветствия автоответчика повтор не запускается.

Локальная проверка: 79 Python unittest проходят. Включены воспроизведения гонки двух create, cancel до created, отклонённого create, поздней STT, продолжения короткого фрагмента, повторного pre-roll, сохранения визита с исправлением времени и неизвестного аргумента инструмента. Неверные аргументы инструмента возвращаются модели как исправимая ошибка с допустимыми полями, не как исключение пайплайна; исходная схема функции сохраняется. Отдельно проверена фактическая схема контекста: закреплённая версия Pipecat не преобразует Literal автоматически, enum добавляется явно к нормализованной схеме, в том числе после повторного открытия диалога. Для исправления перефразированной цитаты CALL_STATE и ошибки инструментов содержат три последние исходные реплики сотрудника.

Скрипт `apps/pipecat-hypothesis/probe_turn_fixes.py` выполняет одинаковые синтетические сценарии перезвона и визита через реальный Realtime API и опционально реальный ElevenLabs. Он не звонит, не отправляет CRM-диалоги и имитирует только подтверждения воспроизведения. Запуск в контейнере:

```sh
docker compose -f compose.pipecat.yaml exec -T pipecat python probe_turn_fixes.py --provider openai_mini --audio-tts
docker compose -f compose.pipecat.yaml exec -T pipecat python probe_turn_fixes.py --provider openai --audio-tts
```

Первый API-прогон обнаружил дополнительный цикл неверного инструмента Mini и служебную фразу полной модели перед прощанием. Эти случаи учтены в enum, диагностике ошибок инструмента и удержании возможного закрытия. Успешная техническая проба не оценивает естественность русского языка Mini и не заменяет звонок с настоящими VAD, перебиваниями и Voximplant.

Технически корректный визит не доказывает исправления всех языковых и инструментальных ошибок Mini. Полная модель остаётся более надёжным вариантом по этим двум сценариям; для скорости нужен новый живой звонок после исправления гонок.
