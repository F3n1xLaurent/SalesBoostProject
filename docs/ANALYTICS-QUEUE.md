# Очередь аналитики

После завершения звонка бэкенд быстро сохраняет его завершение и освобождает
телефонию. Тяжёлая обработка — получение записи, повторное распознавание,
оценка и отчёт — ждёт слот общей FIFO-очереди. Первичная аналитика тренировок,
фоновая достройка и ручное переполучение отчётов используют тот же лимит.

По умолчанию одновременно работают **две задачи**. Настройка в `.env`:

```dotenv
ANALYTICS_CONCURRENCY=2
```

Допустимые значения — целые числа 1–8. Неверное значение даёт безопасный
default 2. Изменение применяется после перезапуска приложения. Это лимит
обработок, а не отдельных HTTP-запросов: внутри одного отчёта некоторые
проверки по-прежнему параллельны. Живое общение бота в звонке в эту очередь
не попадает. Лимит прозвонов настраивается отдельно.

## Ожидание и повторы

Пока задача ждёт слот, API отдаёт `status: waiting`, `waitingForSlot: true`
и позицию в текущей очереди процесса. Пользователь видит «Отчёт в очереди на
обработку». Кнопка переполучения по двухминутному таймеру в этом состоянии
не появляется. Повторный POST для уже ожидающего отчёта возвращает 202,
не создавая второй задачи. Таймер выполняемой обработки начинается при
получении слота, а не при постановке в очередь.

Ручная замена действительно долгой выполняемой обработки сохраняет защиту
от публикации устаревшего результата. Старая работа продолжает занимать свой
слот до фактического завершения, поэтому замена не обходит лимит. Вложенный
перезапуск того же звонка использует слот родительской задачи без повторного
захвата. Контекст учёта расходов переносится вместе с задачей.

## Сохранение после перезапуска

Первичная обработка завершённых звонков сохраняет входные данные в SQLite,
в таблице `call_analysis_jobs`, включая исходную расшифровку и время завершения.
После перезапуска приложение восстанавливает задачи `queued` и прерванные
`processing`. Затем раз в 10 секунд проверяет ожидающий backlog. Повторный
вебхук не создаёт второй анализ завершённой задачи и не меняет уже определённый
исход звонка. После завершения payload очищается из строки очереди.

Состояния `done` и `failed` автоматически не перезапускаются. Ошибка не создаёт
бесконечную платную петлю. Явное переполучение может создать новую попытку;
устаревшая попытка не перезапишет состояние новой.

Очередь повторной генерации и аналитики тренировок ограничена тем же числом
слотов, но её JS-задачи не сериализуются в БД. После рестарта для них остаются
существующие механизмы достройки при открытии отчёта/ручного переполучения.
Только первичный backlog звонков восстанавливается автоматически из этой
новой таблицы. При аварии после оплаченного ответа API, но до сохранения
результата, восстановленная задача может повторить запрос: exactly-once
оплату внешнего API этот механизм не гарантирует.

Текущая реализация предназначена для **одного процесса приложения**, как в
`compose.prod.yaml`. Второй процесс/реплика потребует общего распределённого
ограничителя и lease на задачи; увеличивать число реплик с этой очередью нельзя.

## Выкладка

Нужна миграция `20261110120000_add_call_analysis_queue`. Новый Prisma Client
должен быть сгенерирован при сборке. До запуска новой версии приложения
применить миграции к продовой БД:

```sh
docker compose -f compose.prod.yaml run --rm app npx prisma migrate deploy
```

Команда должна использовать **уже собранный новый образ**, содержащий миграцию.
Без таблицы обработка звонков завершится ошибкой сохранения задачи; обхода
очереди с неограниченным запуском запросов не предусмотрено. Продовую миграцию
и выкладку в рамках этой задачи не выполняли.

## Проверки

Автоматические проверки включают: burst из 30 задач с максимумом 2 активных;
FIFO; освобождение слота после ошибки; перенос контекста расходов; отсутствие
повторной постановки ожидающей задачи; вложенную обработку без deadlock;
быстрое сохранение завершения звонка до получения слота; миграцию и восстановление
на отдельной SQLite-базе; защиту от повторного захвата/устаревшего результата;
восстановление после отключения Prisma Client и обработку повреждённого payload.
Тесты используют заглушки провайдеров, платные API не вызываются.
