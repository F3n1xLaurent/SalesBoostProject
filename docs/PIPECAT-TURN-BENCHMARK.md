Изолированный замер задержки распознавания, определения конца реплики и первого текста.

Результаты прямого потокового Gemini (по 5 попыток на вариант; серия завершилась ошибками сервиса Gemini): [PIPECAT-GEMINI-DIRECT-BENCHMARK.md](PIPECAT-GEMINI-DIRECT-BENCHMARK.md).

Успешная последующая серия с Gemini 3.5 Flash-Lite: Nova-3 2771,24 мс и Flux 3098,28 мс до первого текста, по 5/5 успешных попыток. Другие проверенные модели, разброс и ограничения: [PIPECAT-GEMINI-OTHER-MODELS.md](PIPECAT-GEMINI-OTHER-MODELS.md). --gemini-model выбирает модель только для отдельного скрипта.

Скрипт: `apps/pipecat-hypothesis/benchmark_turns.py`. Использует существующее Python-окружение прототипа и дополнительный SDK из `requirements-benchmark.txt`. Docker-сервис и production-зависимости для него менять не нужно. В этой сессии окружение находится в `/tmp/salesboost-pipecat-locked`; вместо `python` в командах ниже можно использовать `/tmp/salesboost-pipecat-locked/bin/python`.

Для прямого потокового Gemini используйте отдельный режим. Нужны DEEPGRAM_API_KEY и GEMINI_API_KEY в сохранённом корневом `.env`; GEMINI_PROJECT_NUMBER для Gemini Developer API по ключу не требуется. Pipecat GoogleLLMService вызывает `generate_content_stream`; прежний маршрут ProxyAPI также использовал потоковый метод. Этот режим меняет маршрут к Gemini, не превращает его в Gemini Live и не передаёт туда исходное аудио: поток STT идёт в Deepgram, затем текст — в Gemini, ответ Gemini поступает частями.

```sh
python apps/pipecat-hypothesis/benchmark_turns.py --check --gemini-provider gemini --variants nova3 flux
python apps/pipecat-hypothesis/benchmark_turns.py \
  --gemini-provider gemini --variants nova3 flux --request-interval 15 \
  --input-wav storage/pipecat-benchmarks/input.wav \
  --runs 5 --output storage/pipecat-benchmarks/turns-gemini-direct.json
```

Интервал 15 секунд ограничивает частоту начала попыток, но не гарантирует квоту конкретного Free Tier проекта. Отчёт сохраняет маршрут, потоковый режим, неуспешные попытки и дополнительное время от передачи контекста в LLM до первого текста. Доступность модели и Free Tier нужно проверять настоящим запросом перед серией; перехода на другую модель или платный аккаунт автоматически нет.

В корневом `.env` нужны `DEEPGRAM_API_KEY`, `OPENAI_API_KEY` и `PROXYAPI_API_KEY`. Ключ Deepgram отправляется только в нативный Deepgram API; Gemini работает через существующий маршрут ProxyAPI.

```sh
python apps/pipecat-hypothesis/benchmark_turns.py --check
python apps/pipecat-hypothesis/benchmark_turns.py \
  --input-wav storage/pipecat-benchmarks/input.wav \
  --runs 5 --output storage/pipecat-benchmarks/turns.json
```

Вход — синтетическая русская запись PCM16 little-endian, mono, 16000 Hz, одна непрерывная реплика. Не передавайте реальные звонки или CRM-контекст. Тестовая запись первого запуска: «Да, автомобиль ещё в наличии и пробег в объявлении указан верно». Запись озвучена один раз ElevenLabs и используется одинаково для всех вариантов.

Сравниваются:

- `gpt-realtime-2.1`, reasoning low, native TTS выключен, server VAD выключен, существующий GatedRealtime + Silero (100/200 мс) + Smart Turn (fallback 1500 мс), параллельный `gpt-4o-transcribe` на русском.
- `nova-3`, русский язык, Deepgram endpointing выключен, Silero/Smart Turn с теми же параметрами. Pipecat ждёт завершения распознавания перед отправкой текста в Gemini 3.8 Flash, thinking low.
- `flux-general-multi`, language hint ru, EOT threshold 0.7, timeout 5000 мс, eager EOT выключен. Границы реплик определяет Flux; локальных Silero/Smart Turn нет. Текст отправляется в тот же Gemini через ProxyAPI.

Порядок вариантов меняется по кругу. По умолчанию — 5 попыток каждого варианта, всего 15. Аудио идёт с темпом живого потока, блоками 80 мс, с 500 мс тишины перед записью и до 8 секунд после. Соединения создаются заново для каждой попытки; сетевое подключение до начала подачи аудио исключено, первая генерация Gemini использует новое HTTP-соединение. Базовый промпт общий, короткий, синтетический; существующий GatedRealtime дополнительно синхронизирует свою служебную память CALL_STATE. Это сравнение работающих схем с общим аудио, а не контрольный эксперимент с полностью идентичным эффективным контекстом или воспроизведение полного бизнес-диалога.

Общая точка отсчёта — конец последнего окна PCM длительностью 10 мс с пиком >=300. Это независимый акустический ориентир, а не время срабатывания конкретного VAD. JSON хранит времена определения конца реплики, финального текста STT, первого текста LLM, сами тексты и события. Поскольку STT и LLM в Realtime работают параллельно, складывать их задержки нельзя.

Неудачные попытки и преждевременные окончания не входят в медиану. Смотрите число `valid` рядом с `attempts`, ошибки подключения и расшифровки: пять попыток не гарантируют пять успешных замеров. Если меньше пяти — результат неполный. JSON сохраняется после каждой попытки в игнорируемом `storage/` с правами 0600.

Скрипт не измеряет TTS, телефонное воспроизведение, barge-in, удержание контекста при длинных паузах или качество сложных диалогов. Первый текст не равен первому слышимому звуку. Короткий промпт и небольшая выборка не позволяют считать победителя универсально лучшим для звонков.

Все 15 расшифровок сохраняют полную исходную фразу; различия только в пунктуации и «е/ё». Преждевременных границ и ошибок во время измеряемой подачи аудио не было. Перед пятым замером Flux было одно событие ошибки подключения с последующим успешным подключением до начала подачи аудио; оно сохранено в JSON.

Nova-3 быстро даёт текст, но медиана от границы реплики до первого текста Gemini составила 4206,60 мс. У Flux тот же промежуток — 1824,25 мс, при более позднем EOT. Причина разницы времени Gemini между этими двумя сериями не установлена: это наблюдаемые задержки конкретных запросов через ProxyAPI, а не доказательство влияния STT на скорость модели. У Realtime соответствующая медиана — 724,11 мс. Медианы отдельных этапов нельзя механически складывать.

По этому замеру текущая Realtime-схема быстрее; оснований переходить на Deepgram + Gemini ради скорости не получено. Качество контекста, длинные паузы и перебивания нужно проверять отдельными сценариями. Ответы моделей сохранены для ручного анализа; смысловое качество автоматически не объявляется пройденным.
