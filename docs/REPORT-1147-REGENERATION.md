## Исправления

1. Повторная подготовка использует сохранённый сценарий и критерии именно этого звонка из `CallPlanCall`, если `caseContextJson` содержит только идентификаторы. Для demo сохраняется собственный снимок. Критерии передаются первыми, чтобы ограничения длины контекста не отрезали факты для учебных примеров. Оценка и чек-лист повторно не рассчитываются.
2. Повторное нажатие после двух минут не заменяет токен активной задачи. Раньше новая задача сталкивалась с занятой записью в БД, а старой уже запрещалось публиковать результат. Ожидание в очереди также не запускает дубликат. Завершённая ошибкой задача допускает явный повтор.
3. Общий бюджет формирования отчёта — 300 секунд. Достижение срока прерывает реальные HTTP-запросы и завершает ожидание даже у некорректно зависшей зависимости. Незавершённый отчёт не публикуется; состояние ошибки освобождает очередь и допускает повтор.
4. Примеры восстанавливаются группами не более трёх реплик, максимум две группы одновременно. Повторяются только неуспешные элементы; результаты успешных групп сохраняются. Условия полноты и независимая смысловая проверка сохраняются.
5. Разрешены естественные представления вроде «Это Алина… в „МореАвто“». Отсутствие имени или компании всё ещё отклоняется; корректность конкретных имён проверяет независимый редактор.
6. При явно отмеченном неверном адресе можно заменить номер дома на адрес из сохранённого сценария. Это исключение касается только чисел внутри исправляемого адреса: согласованное время, суммы и прочие корректные числа сохраняются. Неизвестный адрес и изменение времени не проходят проверку.
7. Обращение к ранее известному имени клиента сразу после «Алло» считается продолжением проверки слышимости, а не отдельным ответом по продажам, для которого нужно несколько раз запрашивать оценку.
