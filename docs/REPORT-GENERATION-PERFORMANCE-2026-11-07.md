# Замеры генерации отчётов, 7 ноября 2026

Проверка через платный ProxyAPI, модель `openai/gpt-5.6-luna`. Использованы
синтетические сценарии из каталога тестов; это не отчёты продовых звонков.
Скрипты не записывают отчёты в историю звонков. Расходы записываются в локальный
учёт экономики. Приведённые суммы — оценка этого учёта, не выписка провайдера.

## Что изменено

- Основная оценка звонка сохраняет настроенный `high`. Сборка отчёта из готовой
  оценки использует `medium`, как вспомогательные стадии. Настройки `low` и
  `medium` не повышаются. Версия профиля — `report-staged-v2`.
- В ответе модели один полный улучшенный пример на реплику. Сервер переносит его
  в каждое отдельное замечание этой реплики. Коды, цитаты и проверки всех замечаний
  сохраняются. Текст и роли исходного диалога восстанавливаются сервером.
- Независимые проверки примеров выполняются группами по две реплики, максимум две
  группы одновременно. Проверяются точный хеш кандидата, все идентификаторы
  замечаний, факты, прямой ответ и дословные подтверждения каждого `pass`.
- Повторное исправление получает историю отклонённых кандидатов и накопленные
  замечания, чтобы не переключаться между двумя неполными вариантами.
- Общий бюджет сборки — 300 секунд; один запрос — до 120 секунд, редакторская
  проверка — до 90. Реальный HTTP-запрос отменяется; истёкший бюджет не позволяет
  опубликовать частично проверенный результат. Скрытые транспортные повторы SDK
  отключены; явные ограниченные исправления JSON и качества сохранены.
- В логах стадий есть время, токены и причина окончания без содержимого звонка.

## Сравнение на одинаковом входе

Сценарий `call-changes`: неверные имя, модель, год и пробег, отсутствие ответа об
истории обслуживания и неконкретное приглашение. Одна и та же предварительная
оценка (16 баллов) использована до и после. Хеш сохранённого входа SHA-256:
`4a640bba140e58674342e8ea5276522b398574cf08b2c2779618effd31f6d3b9`.

| Метрика сборки без предварительной оценки | Исходная версия | Итоговая версия |
| --- | ---: | ---: |
| Время | 138,902 с | 34,344 с |
| API-запросы | 3 | 3 |
| Выходные токены, включая рассуждения | 18 542 | 4 479 |
| Существенные замечания | 4 | 4 |
| Проверенные улучшенные примеры | 2/2 | 2/2 |
| Отдельная проверка качества | 6/6 | 6/6 |
| Оценка стоимости сборки | 7,34 ₽ | 1,89 ₽ |

В этой паре сборка быстрее примерно в 4 раза. Первичная оценка до сборки заняла
21,908 с; она не включена ни в время, ни в стоимость строки сравнения. Исходный
первый запрос сборки занял 78,991 с и исчерпал 10 000 выходных токенов целиком на
рассуждения, завершившись `length` без готового JSON. Следующий запрос занял
51,996 с. Это воспроизведённая причина задержки в тесте, а не доказанная причина
конкретных зависаний на проде.

Итоговый файл — `optimized-history.json`, исходный — `baseline.json` в
`/tmp/salesboost-report-benchmark`. Первый ответ редактора итогового запуска
нарушил протокол полноты проверок; повторная проверка того же текста восстановила
полный протокол. Содержательные отклонения не переоцениваются до случайного `pass`.

## Проверка качества и промежуточные результаты

Отдельный оценщик видит исходный диалог, оценку и отчёт без названия запуска,
времени, профиля рассуждений и вердиктов встроенного редактора. Шесть критериев:
все проблемы, главная ошибка, известный контекст, сохранение сильных сторон,
одно полезное уточнение, согласованность данных.

Промежуточная оптимизация дала 47,607 с, но отдельный оценщик нашёл реальный
дефект: после вопроса добавлялась просьба сообщить время и контакт без `?`.
Добавлены локальная проверка таких просьб и соответствующее правило генерации.
Второе замечание оценщика требовало повторить в примере все цифры клиента, хотя
критерий требует сохранять правильные факты исходной реплики менеджера. Этот
спорный вердикт не засчитан как успешная проверка.

Следующий запуск (`optimized-final.json` первого сценария) завершился ошибкой
через 62,372 с: редактор попеременно отклонял отсутствие вопроса о приоритете и
отсутствие конкретного следующего шага. Некачественный отчёт не опубликован.
После этого добавлена передача накопленных замечаний и отклонённых текстов.
Итоговый `optimized-history` прошёл все шесть независимых критериев.

Дополнительный сценарий `call-conditions` проверяет снег, дождь, грязные датчики,
гарантию и сохранение известного времени визита. Промежуточная версия собрана за
33,297 с и получила 6/6 отдельных критериев. Итоговая версия собрана за 42,476 с,
содержит пять замечаний и два проверенных примера; стоимость сборки — 2,90 ₽.
Её отдельная оценка — 5/6: найдено противоречие в исходной оценке звонка.
Чек-лист утверждает, что менеджер не выяснил интересующий автомобиль, хотя
клиент уже назвал GLE. Эта строка присутствует в сохранённом входе и в weaknesses
обоих запусков второго сценария; логика переноса этой строки при оптимизации не
менялась. Таким образом, первый оценщик пропустил существовавший дефект.
Это не засчитано как успешная проверка и не устранено изменением баллов или
ослаблением оценщика. Для этого дефекта требуется отдельная коррекция основной
оценки; ускорение сборки его не исправляет. Артефакты —
`/tmp/salesboost-report-conditions/assessment-optimized-final.json` и `input.json`.

Всего на генерации и отдельные оценки эксперимента, включая неудачные попытки,
по локальному учёту потрачено около 29,14 ₽.

Это небольшая выборка, не p50/p95 и не гарантия сохранения качества на любых
звонках. Измерение включает все повторы и исправления данного запуска. Неуспешные
промежуточные запуски приведены выше; они не исключены из описания эксперимента.
После выкладки стоит сравнить времена стадий и долю отказов на реальных звонках.

## Воспроизведение

Требуется настроенный ProxyAPI. Обе команды платные; `--execute` обязателен.
Для сопоставления скорости сохраняйте предварительную оценку через `--input`.

```sh
node --import tsx scripts/benchmark-report.ts --execute --out /tmp/report-benchmark --label measurement --scenario call-changes
node --import tsx scripts/benchmark-report.ts --execute --out /tmp/report-benchmark --label repeat --scenario call-changes --input /tmp/report-benchmark/input.json
node --import tsx scripts/assess-report-benchmark.ts /tmp/report-benchmark --execute measurement repeat
```

Артефакты содержат полный синтетический отчёт, ответы API, usage и результаты
проверок. Каталог создаётся с правами 0700, файлы — 0600. В репозиторий они не
добавляются. Тесты проверяют границу параллелизма, порядок результатов, отмену
HTTP и вложенный бюджет, копирование полного примера без потери замечаний,
проверку каждого кандидата и передачу истории исправлений. Регрессии отчётов:
184 теста в 14 файлах прошли; `tsc --noEmit` прошёл. Прод не выкатывался.
