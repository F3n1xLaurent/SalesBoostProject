# Автопроверка гипотезы 2

Экран «Realtime-тест» → «OpenAI напрямую + ElevenLabs» → выбрать план → «Запустить автопроверку».
Номер не набирается. Используются реальные OpenAI Realtime и ElevenLabs из `.env`, голос/настройки TTS выбранного плана. Серия расходует баланс API.

Одна серия: 10 независимых сессий, общий чеклист из 17 пунктов, транскрипты, события и стерео WAV (менеджер слева, ИИ справа). Готовые аудиофрагменты менеджера кешируются; для ответов ИИ вызывается реальный потоковый TTS. Менеджер говорит с реальной скоростью, таймеры пауз не ускорены.

## Консоль

```
npm run test:realtime-hypothesis2 -- --list
npm run test:realtime-hypothesis2 -- --plan <id>
npm run test:realtime-hypothesis2 -- --plan <id> --scenarios acknowledgement,interruption --model gpt-realtime-2.1
npm run test:realtime-hypothesis2 -- --plan <id> --checks interruption
npm run test:realtime-hypothesis2 -- --plan <id> --checks identity,answers --reference <runId>
```

CLI использует активного супер-администратора; другой доступный аккаунт можно задать через `--email`. Права на выбранный план проверяются. Ctrl+C останавливает серию. В интерфейсе доступна кнопка «Остановить».

`storage/realtime-regression/<runId>/report.json` и `<caseId>.wav` сохраняются между перезапусками. Через HTTP отчёт и записи доступны только запустившему тест аккаунту. Отчёт можно скачать в JSON. Прогон, процесс которого завершился, отмечается ошибкой. Одновременно запускается одна серия на процесс. Запущенную через CLI серию останавливают в её консоли через Ctrl+C.

## История, сравнение и точечная проверка

История на экране автоматически подхватывает старые `report.json`, включая отчёты первой версии. Список фильтруется по аккаунту и плану, страницы по 30 запусков. Сохранённый отчёт открывается вместе с записью и транскриптом. Новые тесты не перезаписывают старые.

Можно выбрать все проверки, несколько пунктов чеклиста или отдельные сценарии. Кнопки «Проверить пункт», «Повторить сценарий» и «Повторить этот тест» запускают необходимые ветки на той же легенде, если её снимок есть в исходном отчёте. Для пункта «Перебивания» автоматически выбираются и подтверждение «угу», и содержательное перебивание. Проверка только одной ветки не делает весь пункт зелёным. Ошибка в любом запущенном сценарии отражается в итоговом пункте; непроверенные направления остаются «Не проверено».

Новые отчёты сохраняют версию оценщика, снимок выбранного профиля/предмета, настройки TTS, хеш конфигурации и ссылку на исходный прогон. Повтор использует сохранённый профиль и предмет, текущие настройки TTS и выбранную в интерфейсе Realtime-модель. Изменение настроек отражается в сравнении.

Сравнение показывает «было → стало», свидетельства, покрытие сценариями, медиану и p95 задержки по направлению. «Исправлено» и «Ухудшилось» выставляются только при совпадении конфигурации, модели, версии оценщика и набора сценариев этого направления. Старые отчёты без метаданных сравниваются с предупреждением; идентичность их условий не предполагается. Пункт, который не перезапускали, не считается регрессией. Ударения и качество телефонной сети по-прежнему требуют ручного подтверждения.

## Что подтверждается

Автоматические проверки используют реальные события: распознавание подтверждений, остановку аудио, исправление контекста после перебивания, повторы, технические фразы, паузы и наложения на подготовленную речь. Смысловые пункты проверяются отдельно через настроенный `OPENAI_CHAT_MODEL`; вывод требует цитат из транскрипта. При ошибке оценщика, отсутствии свидетельств или незавершённом тесте результат — «Нужно проверить», а не успех. Невыполненные сценарии остаются «Не проверено».

Оценщик ссылается на `turnIndices`, а сервер проверяет существование этих реплик и наличие среди них ответа AI. В отчёте сохраняются объяснение, модель и исходный результат оценки (`assessment`). Это позволяет отличить недостаток данных от ошибки формата. Аудио не требуется для проверки текста: имени, рода, легенды и полноты ответов. Произношение и телефонное качество по-прежнему не сертифицируются текстовым оценщиком.

Метрики «Речь → первое аудио» и «Речь → старт воспроизведения» используют одну точку отсчёта — последнюю голосовую активность менеджера. В обе уже включено ожидание VAD; разность этих метрик отражает дополнительное ожидание проигрывателя. Значение `endpointWaitMs` отдельно считается от commit до создания ответа и не включает VAD. Тайминги распознавания привязаны к конкретному input item и не сбрасываются началом следующей реплики.

Женская ветка добавляет явную тестовую легенду Анны поверх выбранного плана и проверяет род/имя/бюджет/несколько вопросов. Голос остаётся выбранным в плане: для проверки именно женского голоса выберите соответствующий план.

Симулятор использует тот же PCM/WebSocket-обработчик и тот же конвейер генерации, что и звонок; он эмулирует Vox-проигрыватель с 80 мс стартового буфера. Его тайминги **не измеряют реальную сеть/буферы Voximplant**. Ударения, эмоциональность и слышимость по телефонной сети требуют прослушивания и контрольного звонка. Мелодия ожидания синтетическая: можно дополнить корпус реальными записями для большей репрезентативности.

## Перебивания

Вторая гипотеза принимает PCM менеджера во время генерации/озвучки. Короткую фразу распознаёт и классифицирует: «угу/ага» не останавливают речь и удаляются из контекста. Непрерывная речь от 850 мс отдаёт слово менеджеру сразу; короткая содержательная фраза — после распознавания. Отменяются GPT/TTS, очищается очередь воспроизведения. Текстовая история GPT заменяется услышанным префиксом по alignment ElevenLabs; без alignment применяется консервативная оценка. Старые текстовые дельты игнорируются. При следующем ответе бот не должен считать непрозвучавший вопрос заданным.

OpenAI `conversation.item.truncate` предназначен для аудиосообщений. Здесь GPT выдаёт текст, а аудио синтезирует ElevenLabs: поэтому используется удаление текстового сообщения и создание его услышанной части (`conversation.item.delete/create`), не фиктивный truncate внешней дорожки.
