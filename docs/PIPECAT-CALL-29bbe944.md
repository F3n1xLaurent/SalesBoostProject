# Повторный запрос имени и проверка фактического WAV · semantic-7

Исходный звонок `pc-29bbe944-bf7a-46c6-95bf-43ad9f85290a`, версия `pipecat-semantic-6`.

## Что подтверждено

На ходе 2 на «Как можно к вам обращаться?» сформирована и поставлена реплика «Здравствуйте! Меня зовут Андрей. Меня интересует Mercedes-Benz GLE Рестайлинг 2024. Машина ещё продаётся?». Для `controller-7e99b2637e1d47398c6190c2f33c077a` получен телефонный ACK. Сам ACK подтверждает завершение сегмента, но не содержание и разборчивость отдельных слов на линии.

Проверен фактический WAV из банка: `ffbb614bcab0172d2311a123829a0ffbf45b52960977b2e811acfd7ad3f32024.wav`, длительность 8,96 с, PCM SHA256 `33303debaedecb1f78518f2f35b219f39ff1a19d60a76535e755457ae62ad90c`. Его содержимое распознано локально, без подсказки ожидаемого имени:

> Здравствуйте. Меня зовут Андрей. Меня интересует Mercedes-Benz GLE… Машина ещё продается.

«Меня зовут Андрей» находится примерно на 1,02–1,86 с, само имя — 1,48–1,86 с. RMS этого участка −15,31 dBFS, остальной основной фразы −17,81 dBFS: по исходному WAV имя не тише остальной речи. Файл отличается от обычного приветствия без имени (7,84 с, другой PCM SHA256).

Это доказательство наличия имени в подготовленном звуке, а не доказательство того, что оно было различимо в телефонном тракте. Записи телефонного воспроизведения в текущем журнале нет. Причину субъективно пропавшего имени в первом представлении по этим данным установить нельзя; утверждать, что первый WAV был без имени, было бы неверно.

Последующие запросы имеют установленную ошибку контроллера:

- Ход 7: «…как я могу к вам обращаться?» → `name=yes`, но из-за ранее поставленного имени выбран `identity_ack`. Вместо имени прозвучало «Да, всё верно» и следующий вопрос.
- Ходы 22 и 24: «…подскажите ваше имя» / «…как вас зовут?» снова заменены подтверждением. Общий фильтр затем заблокировал уже звучавшее «Да, всё верно» и повторное прощание. Нового аудио с именем не было.

Защита от самопроизвольного повторного представления ошибочно подменила прямой запрос значения подтверждением ранее названного значения.

## Исправления

1. `name=yes/repeat` всегда означает просьбу назвать имя. Если имя уже ставилось в очередь, сама текущая просьба разрешает повтор — наличие слова «повторите» или объяснения «не расслышал» не обязательно.
2. `name_confirmation` применяется только когда собеседник сам произносит правильное имя и просит подтвердить его. Простое «Как вас зовут?» не получает «Да, верно».
3. Разрешение повторить имя действует и в подготовленном пути, и в нативном Realtime. В нативном пути разрешены только ключи представления, без общего обхода для повторных статусов и других фраз. Новое начало речи сбрасывает разрешение предыдущего хода.
4. Первое приветствие с именем в semantic-режиме собирается из отдельных готовых PCM: приветствие → имя → вопрос об объекте. Между компонентами 40 мс. Имя не зависит от результата синтеза длинного составного приветствия; используется тот же отдельный клип имени, что и для повторного ответа. Это изменение цепочки будущих звонков, а не установленная причина отсутствия имени в старом телефонном воспроизведении.
5. В `controller_audio_queued` добавлены `prepared_key`, SHA256 реального PCM и `audio_components` с позициями/длительностями/хешами частей. По одному тексту журнала больше не нужно угадывать источник составного звука.
6. При проверке завершения найден отдельный дефект: парсер отбрасывал соседнее уточнение «дня» из «в три часа дня». Повторное подтверждение 15:00 ошибочно считалось изменённым временем. Сохраняется дословный соседний модификатор утра/дня/вечера/ночи; пороги согласия не снижены.

Общий фильтр повторов сохранён. Не запрошенное повторное представление по-прежнему блокируется, проверка имени не вызывает полного представления, повторный запрос имени не разрешает повторять произвольные статусы. Production pipeline не менялся.

## Проверки

348 Python-тестов, один необязательный пропущен. Новые проверки: три последовательные просьбы назвать имя дают три ответа; запрос после прощания озвучивается и завершение ждёт ACK; имя в нативном пути повторяется по запросу, но повтор статуса остаётся запрещённым; разрешение сбрасывается на новой речи; составное приветствие содержит точные байты отдельного клипа имени; сохранённое уточнение времени не вызывает ложного `changed_time`.

Синтетический API-прогон `pctrl-5fa1efd9-d730-4119-868a-c857ac4d1882`, журнал `pc-8f795b7c-e776-42fd-9ec8-d5783f54f496`: 15/15. Четыре запроса значения имени (первый, повторный, вместе с целью покупки, после прерывания прощания) получают имя. Проверка «Андрей, верно?» не вызывает нового представления. Нативное имя и последнее имя подтверждены симулированным телефонным ACK, цель покупки не потеряна, вопросы плана заданы по одному разу, hangup после ACK. Это реальные Realtime/ElevenLabs/Decisions со входным синтетическим текстом и симулированным телефоном, без PSTN-звонка.

Для содержимого исходного WAV использован локальный `faster-whisper-base` на CPU, `local_files_only=True`, `HF_HUB_OFFLINE=1`, без текстового prompt/keywords. Веса и библиотеки установлены только в `/tmp/pipecat-offline-asr`, runtime Pipecat не получает новой зависимости. Документация локального запуска: [SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper).

Попытка отправить WAV в OpenAI `/v1/audio/transcriptions` была отклонена автоматической проверкой из-за отсутствия отдельного согласия на передачу конкретного файла. Аудио этим запросом не отправлено; проверка выполнена безопасным локальным способом. Из внешней сети скачаны только публичные библиотеки и веса модели. Официальная схема первоначально рассматривавшейся файловой транскрипции: [OpenAI file transcription](https://developers.openai.com/api/docs/guides/speech-to-text).

Исходный PCM и локальная расшифровка, а также отчёты API-проб сохранены в `storage/pipecat-benchmarks/semantic-7/`. Установлен `pipecat-semantic-7`, тот же режим «Смысловой контроллер · эксперимент».
