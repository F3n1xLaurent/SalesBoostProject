# Биллинг компаний

Раздел `/billing` доступен только аккаунтам с ролью `platform_superadmin`. Сервер проверяет роль при каждом чтении и изменении. Заголовок выбранной роли и шаблоны прав не дают доступ к биллингу.

Для каждой компании биллинг по умолчанию выключен: существующие клиенты продолжают работать. При включении новые запуски обзвона и тренажёра требуют действующей оплаты соответствующего модуля. Права сотрудников продолжают действовать независимо от оплаты.

Оплата содержит сумму в копейках, дату платежа, начало и окончание доступа (или бессрочный доступ), модули, обязательный комментарий и статус. Поле комментария подходит для номера договора и описания назначения платежа. Даты в форме интерпретируются в местном часовом поясе администратора; окончание включает выбранный день целиком. В базе сохраняются точные моменты времени UTC.

Доступ объединяет модули всех активных оплат, период которых включает текущий момент. Например, одна оплата на 5000 ₽ открывает обзвон, вторая на 5000 ₽ — тренажёр. Сумма служит учёту: минутных лимитов, баланса, списаний и интеграции с платёжным шлюзом нет.

Суперадмин может изменять предыдущие оплаты и отменять их через форму редактирования. Каждое изменение оплаты или переключателя биллинга атомарно записывается в историю с автором, временем и снимками до/после. Физического удаления оплат нет. Версия записи защищает от перезаписи параллельных правок: при конфликте нужно закрыть форму, обновить данные и повторить изменение.

Проверка действует при запуске нового тренажёра, Telegram-тренировок связанного сотрудника, ручных звонков, каждого задания очереди и плановых звонков перед фактическим набором. Уже начатые сессии можно завершить, результаты и отчёты остаются доступными. Публичные демонстрационные звонки и отдельные тестовые инструменты не относятся к оплачиваемым запускам компании.

Если очередь или расписание дошли до звонка без оплаченного доступа, звонок не набирается, задание получает ошибку. После добавления оплаты такой звонок нужно запустить заново. Автоматического повторения неоплаченных заданий нет.

## Обновление базы

Перед запуском обновлённого сервера примените миграции обычным способом:

```sh
npx prisma migrate deploy
npx prisma generate
npm run build
```

Миграция `20261102120000_add_company_billing` добавляет две таблицы и поле `holdings.billingEnabled` со значением `false`. Она не пересоздаёт таблицу компаний и не включает ограничения для существующих клиентов.

## Проверка

```sh
npx vitest run src/__tests__/billing.test.ts src/__tests__/callPlanTelephony.test.ts
npm run build
```

Тесты используют отдельные временные SQLite-базы. Проверяются периоды и объединение модулей, серверное ограничение роли, создание/редактирование/отмена оплат, история, конфликт версий, изоляция компаний, миграция с существующими данными и запрет набора без доступа.
