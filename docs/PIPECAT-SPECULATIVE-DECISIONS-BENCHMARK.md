# Параллельная подготовка реплики + удалённый Decisions

13 ноября 2026. Отдельный бенчмарк идеи: пока менеджер говорит, Mini готовит следующую реплику и ElevenLabs синтезирует её в приватный буфер. После ответа менеджера отдельный HTTP-запрос Decisions разрешает использовать аудио, требует новый ответ или выбирает ожидание.

Рабочая гипотеза и production не менялись. Телефонных звонков, CRM-записей, исполнения инструментов и реального воспроизведения Voximplant нет. Этот тест заменяет прежний локальный выбор заготовки **настоящим сетевым запросом** `https://api.proxyapi.ru/v1/decisions`, модель `openai/gpt-6-luna-decisions`, уже используемая в проекте для другой классификации. Форма запроса проверена по [документации ProxyAPI](https://proxyapi.ru/models/openai/gpt-6-luna-decisions); назначение Decisions — по [официальной документации OpenAI](https://developers.openai.com/api/reference/resources/decisions/methods/create). Протокол ProxyAPI отличается от прямого OpenAI, в стенде они не смешиваются.

## Метод

Сохранён демонстрационный план и вымышленный автомобиль из [предыдущего бенчмарка](PIPECAT-PREPARED-REPLIES-BENCHMARK.md). По пять повторов семи сценариев на вариант: знакомство, следующий вопрос после наличия, следующий вопрос после пробега, несколько ответов со встречным вопросом, вопрос про наличные/кредит, исправление пробега, просьба подождать. Одинаковые история и CALL_STATE в парных попытках; порядок двух вариантов чередуется.

**Current:** готовый текст менеджера → текущий полный промпт с legacy adapter → Mini low → SpeechFilter → настоящий ElevenLabs v4 turbo fast_sentence → локальный пакет VoxSerializer.

**Decisions:** отдельная Realtime Mini low заранее получает только предыдущую историю и следующую тему из плана. Она генерирует новый текст, а отдельный экземпляр настоящего TTS складывает звук в приватный буфер. Текущий ответ менеджера и ожидаемая метка теста генератору не передаются. После получения ответа проверяется именно фактически сгенерированная реплика целиком. `use` дожидается готовности полного PCM и выдаёт его через тот же сериализатор; `regenerate` сразу запускает тот же путь Mini + TTS, что у Current; `wait` не выдаёт аудио.

На ошибке HTTP, неизвестном действии, отсутствии/некорректности вероятности подготовленное аудио не выдаётся: измеряется обычная генерация после ошибки. Таймаут Decisions 1.8 секунды, автоматических повторов нет. Используется один HTTP-клиент с keepalive 60 секунд, первый запрос с установлением соединения не исключается из статистики. На исправность разбора, неопределённые значения, явный дополнительный порог и HTTP 503 выполнено восемь локальных проверок без сети.

### Время подготовки

Для повторяемости ответ менеджера считается полученным через **1500 мс после запуска предгенерации**. Это искусственная фора, не измеренная длительность речи человека. Генератор работает параллельно этим 1500 мс. Таймер основного ответа запускается после этой форы; если текст кандидата ещё не готов, его ожидание включается, затем запускается Decisions. Проверка кандидата может идти одновременно с завершением TTS. Если выбран `use`, а полного PCM ещё нет, оставшееся ожидание также входит в результат.

Два TTS-экземпляра и два Realtime-сокета заранее прогреты, один для обычного/нового ответа, другой для скрытой подготовки. Приватный буфер не попадает в измеряемый выход до `use`. Текст кандидата готов после завершения его генерации Mini. Полный буфер считается готовым после TTSStopped и 150 мс дренирования маркеров стенда; эти 150 мс могут увеличить ожидание позднего кандидата. Отвергнутая подготовка в этом стенде завершается и отбрасывается, а не отменяется: это учитывает лишнюю реальную работу, но не проверяет отмену provider TTS.

### Политика Decisions

В основном замере используется прямой выбор API `use` / `regenerate` / `wait`, без дополнительного порога вероятности. Все вероятности сохраняются; это эксперимент, а не настроенная политика принятия решений для настоящих звонков. Условие для `use` включает уместность, отсутствие уже закрытой темы, встречного вопроса, важной поправки, служебного текста или домыслов. При сомнении инструкция требует `regenerate`.

Предварительная проба `psd-4cedf29e-bf3e-449f-8345-979a7d4c5e4d` использовала порог 0.85 и исключена из итогов. Он отклонил два из трёх `use` (вероятности 0.78 и 0.70); также первоначальная общая проверка порога превращала `wait` с 0.81 в новую генерацию. Для основного замера `wait` принимается непосредственно, порог опционален только для `use`, по умолчанию 0. API-запрос и его критерии после этой пробы не менялись. Сравнение порогов на пяти повторах отдельно не проводилось; безопасный порог для production этим не выбран.

### Что этот стенд не измеряет

STT, VAD/Smart Turn, реальная длительность реплики менеджера, сеть/буфер Voximplant, время до слышимого голоса, перебивания и политику отмены. Не проверяются бизнес-результаты инструментов; их схемы у обычной генерации сохранены, но вызовы не исполняются. Возможная начальная тишина PCM не удаляется. Пакет на сервере не означает звук в телефоне.

Текущая Mini в живой гипотезе может запускать ответ до финальной STT. В этой схеме Decisions получает готовый текст; ожидание распознавания в таймер не входит и может уменьшить реальный выигрыш. Фора 1.5 секунды также не гарантируется короткой репликой менеджера.

«Попадание»/«промах» — группы контрольных сценариев, а не предсказанная доля попаданий на настоящих звонках. Уместность заранее сгенерированного текста сама может оказаться плохой; несовпадение с ожидаемой меткой сценария требует просмотра кандидата, а не автоматически означает ошибку классификатора. Скорость ошибочно принятой реплики не считается доказательством пользы.

## Результаты пяти проходов

Отчёт `psd-e0a8d296-8711-44db-9734-ffe14c5bb443`. Все 70 парных попыток завершены, по пять на каждый сценарий и вариант. Нет ошибок Decisions, предгенерации или отсутствующего аудио на 60 ожидаемых ответах. Совпали SHA256 входов Current/Decisions и снимок плана с предыдущим бенчмарком. Для трёх разных групп одинакового предыдущего контекста совпали хэши входов предиктора: генератор действительно не видел текущий ответ менеджера. Все 14 использованных PCM совпали с приватным буфером; чужие поздние аудиофреймы не зарегистрированы.

По парным попыткам ускорение было в 13/15 предсказуемых переходов, медиана парного выигрыша 622.787 мс. В группе адаптации ускорение оказалось только в 3/15, медиана парной потери — 183.441 мс. Разница групповых медиан и медиана парных разниц — разные статистики.

Медиана самого HTTP Decisions — **269.900 мс**, диапазон 209.616–773.448 мс, включая первый запрос. По фактически принятым 14 кандидатам полный путь до пакета занял медианные **276.704 мс**. По 16 решениям `regenerate` — 1560.892 мс. Эти строки группируются по фактическому решению, предыдущая таблица — по исходному сценарию; их не следует смешивать.

### Решения и качество кандидатов

35 запросов дали **14 use, 16 regenerate, 5 wait**. Все три сценария необходимости адаптации отклонены во всех пяти повторах; просьба подождать принята как wait во всех пяти. В этих сценариях неподходящая подготовленная реплика не попадала в выходной буфер. Это проверка на данном маленьком корпусе, не доказательство общей точности или безопасности классификатора.

Автоматическая метка `wrongChoices=1` означает несовпадение с ожидаемой группой сценария, а не установленную ошибку Decisions: на третьем повторе вопроса о пробеге предиктор написал «Я пока не получил(а) от вас ответ по предыдущему вопросу…». Такой кандидат плохо подходил к уже полученному ответу. Decisions обоснованно выбрал новую генерацию, и её реальное время вошло в итог. В другом принятом кандидате осталась форма «Я хотел(а) уточнить…»: семантическая уместность не гарантирует естественную озвучку или правильное грамматическое оформление.

Предиктор иногда проговаривал техническую предпосылку о ещё не полученном ответе. Это отдельная проблема его инструкции; критерии классификатора и текст генератора во время основного замера не исправлялись. Семантика всех fallback-ответов, выполнение инструментов и качество интонации не оценены как пройденные проверки.

Текущий текстовый стенд озвучивал ответ на просьбу подождать в 5/5, Decisions молчал в 5/5. Краткое подтверждение ожидания само по себе не считается ошибкой; это не проверка всех ограничителей настоящей гипотезы.

### Успевает ли подготовка за 1.5 секунды

Текст кандидата был готов к моменту ответа в **35/35**, полный PCM — только в **4/35**. Медиана готовности текста после запуска предиктора — **797.092 мс**, полного аудио — **1707.536 мс**, включая дренирование стенда. Часто оставшийся TTS успевал завершиться параллельно запросу Decisions; ожидание позднего PCM уже учтено в первом пакете.

Подготовлены все 35 кандидатов, использованы 14, остальные 21 отброшены. У предиктора дополнительно 7110 input tokens и 2168 output tokens; у Decisions — 16810 input tokens. Также реально синтезировалась вся подготовленная речь. Это дополнительная работа к обычным ответам, не экономия запросов. Денежная стоимость не измерялась.

### Сверка с предыдущими цифрами

В предыдущем тесте готовый PCM с локальным правилом давал пакет за 2.008 мс; здесь реальная предгенерация и сетевой Decisions дают около 278 мс на предсказуемых переходах. Это существенно быстрее обычной Mini + TTS на этих переходах, но уже не почти мгновенное решение. Нельзя просто прибавить фиксированное время Decisions к прежним 2 мс: новая генерация кандидата иногда не успевает подготовить весь звук.

Практическая оценка: перспективный ускоренный путь для предсказуемых вопросов. Обязательная последовательная проверка каждого ответа добавляет задержку на промахах; устойчивое общее ускорение на этой смеси не доказано. Следующий критерий — выигрыш конец речи → слышимый ответ с реальной STT и длительностью ответов менеджера, вместе с корректностью и естественностью кандидатов. Гипотеза оставлена без изменений.

Артефакт: `storage/pipecat-benchmarks/speculative-decisions/psd-e0a8d296-8711-44db-9734-ffe14c5bb443.json`, mode 600. Проверки синтаксиса Python, целостности парных входов, изоляции предсказания, PCM и `git diff --check` прошли.

## Воспроизведение

Нужны те же временные модули `probe_dialogue_state.py`, `probe_prepared_replies.py` и `/tmp/dsm-fixture.json`, что в предыдущем стенде. Дополнительно:

```sh
docker exec -i salesboost-pipecat-pipecat-1 python -c 'import sys; from pathlib import Path; Path("/tmp/probe_speculative_decisions.py").write_text(sys.stdin.read())' < apps/pipecat-hypothesis/probe_speculative_decisions.py
docker exec -e LOGURU_LEVEL=ERROR -e PYTHONPATH=/app:/tmp salesboost-pipecat-pipecat-1 python /tmp/probe_speculative_decisions.py --fixture /tmp/dsm-fixture.json --runs 5 --lead-ms 1500 --use-threshold 0
```

Контейнер не перезапускается. Ключи берутся из его окружения, не печатаются и не включаются в отчёты. Полный JSON с входами, кандидатами, вероятностями и временными метками сохраняется в `/data/logs/psd-<UUID>.json`, mode 600.
