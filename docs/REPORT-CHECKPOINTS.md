# Продолжение генерации отчёта после сбоя

`voice_call_sessions.reportCheckpointJson` и `trainer_sessions.reportCheckpointJson`
хранят внутренний черновик, завершённые примеры, проверенные заключения и историю
отклонённых кандидатов. Черновик не публикуется в `evaluationJson`.

После ошибки повторная генерация продолжает сохранённый отчёт. Успешные группы
ремонта сохраняются сразу, независимо от остальных запросов. Готовый пример
снова отправляется независимому проверяющему только при изменении текста,
замечаний, предшествующего диалога или фактов сценария. Заключение повторно
проверяется локально: совпадение хеша, все checks, дословные evidence.
Неопределённый статус `review` не кешируется. Отклонённый пример получает
исправление, а его предыдущие ошибки передаются редактору.

Изменение исходной расшифровки, оценки, сценария, модели или общих правил
проверки сбрасывает несовместимый черновик. Технические тайминги реплик,
производные поля отчёта и realtime-телеметрия не меняют совместимость.
При несовместимом изменении валидаторов нужно увеличить `VERSION` в
`src/voice/reportCheckpoint.ts`.

Сохранение использует сравнение предыдущего значения и снимка исходных полей:
устаревший процесс не перезапишет новую попытку или изменённый звонок.
Черновик удаляется одновременно с записью готового отчёта, а не при возврате
из генератора. Это сохраняет результат и при ошибке финальной записи.

Для установки: `npx prisma migrate deploy`, затем `npx prisma generate` и
обычная сборка/перезапуск приложения. Миграция
`20261112120000_report_checkpoints` добавляет два nullable TEXT-поля.
Старые неудачные попытки, сделанные до этого изменения, черновика не имеют.

Проверки без внешних запросов: `reportCheckpoint.test.ts` и
`reportCheckpointPersistence.test.ts`. Проверяются переход первоначальной
генерации в повторную, сбои отдельных групп, сохранение валидных примеров,
инвалидация, параллельная запись и восстановление после переподключения SQLite.
