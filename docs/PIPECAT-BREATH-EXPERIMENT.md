# Эксперимент: короткий вдох во время ожидания ответа

Semantic-17, отдельный флаг `PIPECAT_BREATH_EXPERIMENT` (по умолчанию false). Для текущего локального теста включается в корневом `.env`. Основные звонки и гипотеза используют один semantic-сервис.

Звук — один сгенерированный ElevenLabs Sound Effects нейтральный короткий вдох: `apps/pipecat-hypothesis/audio/breath.wav`, PCM16 mono 16 кГц, 640 мс. Он не привязан к конкретному голосу. Подготовка отдельной нормализованной копии выполняется до набора; генерация звука через API при звонке не вызывается. Параметр громкости 0,18 применяется к постоянному RMS-ориентиру 6500, а не к случайному уровню исходной генерации; пик ограничен 8192 (−12 дБFS). Исходный файл можно заменить WAV с тем же форматом длительностью до секунды. Нормализация и фактический RMS сохраняются в `breath_configured`.

## Когда играет

- После завершения реплики сотрудника по Silero/Smart Turn, через 300 мс после commit. Только при подтверждённой человеческой линии и начатом разговоре, если нет агентского аудио/завершения и менеджер ещё не возобновил речь до запуска таймера.
- Не чаще раза в 20 секунд. Это короткая отдельная реакция, не цикл дыхания и не замена готовым голосовым ответам.
- Если менеджер начинает говорить **во время уже запущенного вдоха, вдох не отменяется**. Команда barge-in `clear_media` также его не останавливает. Если менеджер возобновил речь до запуска — устаревший таймер не начинает новый звук.
- Готовность актуального PCM/TTS ИИ отправляет `stop_breath`. Voximplant дополнительно останавливает вдох при `begin_output`. Это касается и коротких озвученных реакций агента.
- Звук прекращается при окончании звонка. Ошибка/отсутствие файла отключает только этот эффект.

## Транспорт

Отдельный URLPlayer Voximplant, заранее загруженный в paused-состоянии; воспроизведение однократное. Микшируется с постоянным фоном и исходящим голосом через существующую конференцию. Подписанный WAV использует прежний маршрут `/pipecat/background/<hash>.wav` и не попадает в список фоновых треков.

Вдох не проходит через Pipecat TTS, не меняет transcript, `SpeechLedger`, вопросные ID или playback ACK основного ответа. Он не задерживает начало ответа и не удерживает завершение звонка. Входящий поток сотрудника по-прежнему отправляется в STT отдельно. События `breath_configured`, `breath_requested`, `breath_playback`, `breath_stop_requested` доступны в диагностике. Vox-событие started подтверждает принятие команды запуска плеера, а не услышанное абонентом содержимое.

## Включить / убрать

В корневом `.env`:

```dotenv
PIPECAT_BREATH_EXPERIMENT=true
PIPECAT_BREATH_VOLUME=0.18
```

Затем `npm run pipecat:up`. Чтобы убрать эксперимент: заменить true на false и выполнить ту же команду. Базовый фон при этом сохраняется.

## Проверки

439 Python-тестов и 15 VM-проверок обоих Vox-сценариев прошли. Проверены выключенный режим, IVR, возобновление речи, отмена устаревшего таймера, частота, сохранение вдоха при речи менеджера, остановка при готовности/начале голоса ИИ и независимость от аудиоочередей. Реальная загрузка подписанного WAV через backend вернула HTTP 200 и корректный RIFF/WAV. Телефонный звонок не выполнялся: громкость, естественность и прогрев URLPlayer нужно оценить на слух на живой линии.

Создание исходного эффекта использует [ElevenLabs Sound Effects API](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert), а не озвучивание слова «вздох». Последний звонок `2c51ef45-01f7-4086-92dc-51ab20548a7a` был до этого изменения: semantic-16, без ошибок в диагностике, медиана speech_to_playback около 2,28 с.

Усиление после первого теста: [разбор ecbc06b2](PIPECAT-CALL-ecbc06b2.md). Новые WAV имеют другой хеш, поэтому старый тихий файл не используется из кеша URLPlayer.
