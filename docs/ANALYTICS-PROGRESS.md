# Подготовка аналитики в интерфейсе

Общий экран `AuditAnalyticsReport` показывает три подтверждённых этапа:

1. Расшифровка диалога.
2. Первоначальная аналитика.
3. Подготовка полного отчёта.

`analyticsProgress` в ответе `/api/admin/audits/:id` содержит `stage`,
`status`, `transcriptReady`, `evaluationReady`, `message`. Статусы:
`waiting`, `processing`, `ready`, `failed`, `unavailable`.

Статус звонка и статус аналитики независимы: нулевой предварительный балл
не означает ошибку генерации. Непринятый звонок показывается без спиннера.
Время ожидания не используется для имитации завершения этапа или процентов.

Реальная текущая стадия отслеживается в контексте фоновой задачи:
финализация звонка → `evaluateSessionV2` → `requestReportJson`.
Для тренажёра применяется тот же механизм при финализации тренировки.
Готовность сохранённых данных подтверждается чтением БД; после перезапуска
процесса без работающей задачи показывается ожидание, не выдуманный прогресс.
Трекер и дедупликация задач действуют в пределах одного backend-процесса.

Открытие отчёта больше не ждёт LLM-генерацию внутри HTTP-запроса. Если оценка
уже сохранена, но полный отчёт отсутствует, запускается дедуплицированное
фоновое дополнение. Оно не запускается параллельно основной финализации.
Ошибочный запрос не повторяется при каждом опросе страницы (30 минут
защитного интервала). Сохранение дополнения проверяет актуальную версию
evaluationJson, чтобы не перезаписать результат конкурентной финализации.
Правила авторизации и область доступа к записи остаются прежними.

Открытый экран проверяет статус раз в 5 секунд, без наложения запросов.
Готовый отчёт отображается сразу после успешного обновления. При временном
сбое сети проверка повторяется; при ошибке обработки, отсутствии разговора,
удалении записи или закрытии экрана опрос останавливается. Запросы чтения
не кэшируются, текущий запрос отменяется при закрытии окна.

Через две минуты ожидания в статусах `waiting`/`processing` появляется кнопка
«Переполучить отчёт». Для уже старого отчёта используется `startedAt` сервера;
дополнительно ведётся независимый отсчёт с открытия экрана. Изменение,
отсутствие, некорректность или будущее значение серверного времени не продлевают
локальный срок ожидания. Переходы между этапами и опрос статуса не сбрасывают
его. После успешного ручного перезапуска начинается новый отсчёт.

Анимация включена только у действительно работающей стадии и отключается
при `prefers-reduced-motion`. Изменения объявляются через `role="status"`.
Платные тестовые звонки и генерации при проверке реализации не запускались.
