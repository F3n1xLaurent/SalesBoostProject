## Аудио, реплики и перебивания

Вход Voximplant: JSON Media Streams с base64 PCM16 little-endian, mono, 16 кГц. Silero и Smart Turn работают на 16 кГц. Pipecat пересэмплирует вход OpenAI в 24 кГц; TTS и выход Voximplant используют PCM16 16 кГц. Не используются MP3, WAV-заголовки в транспортном потоке или переинтерпретация частоты. Пакеты вывода Pipecat — 20 мс. Неожиданные кодеки, частоты, стерео и неполные PCM-сэмплы отклоняются.

Silero: старт 100 мс, окно тишины 200 мс. `LocalSmartTurnAnalyzerV3` решает завершённость реплики, с предельной тишиной 1,5 с. Server VAD OpenAI отключён; автоматические перебивания стартовой стратегии Pipecat также отключены. Обычная реплика OpenAI запускает ответ по Smart Turn без ожидания расшифровки.

При речи поверх ответа короткая реплика сначала распознаётся. Только полностью короткие `угу/ага/мгм` (включая повторения, менее 850 мс) игнорируются; `ага, но цена другая`, `стоп`, `нет` и `да` не попадают в этот фильтр. У OpenAI игнорируемый аудиоэлемент удаляется из server-side conversation, текст не добавляется в историю. Это сознательный компромисс: содержательное короткое перебивание ждёт STT, иначе невозможно отличить «ага» от «ага, но…».

Продолжительная речь подтверждает перебивание без ожидания STT: 850 мс плюс 200 мс окна VAD, чтобы короткое подтверждение с последующей тишиной не срабатывало как длинная речь. После подтверждения `InterruptionFrame` отменяет генерацию/TTS и локальную аудиоочередь, сценарий вызывает `clearMediaBuffer()` в Voximplant. Поздние текст/Function Calling отменённого ответа и аудио отменённого TTS-контекста отбрасываются. Для OpenAI сохраняется pre-roll 1,5 с после очистки входного буфера. Полный текст прерванного ответа удаляется из истории провайдера: точное восстановление услышанного префикса по телефону в этом прототипе не реализовано.

Каждый сегмент воспроизведения имеет уникальный tag. `end_call` только ставит намерение завершить разговор; отбой разрешается после окончания генерации, TTS, отправки и подтверждения `onmediaended` для всех актуальных сегментов. Поздний callback отменённого tag не подтверждает новый ответ. Локальная длительность аудио не заменяет подтверждение Voximplant. Отсутствующее подтверждение не считается нормальным завершением; пяти­минутный лимит теста заканчивает звонок как ошибку. События Voximplant могут добавлять задержку определения окончания воспроизведения; измерить её можно только в реальном звонке.

Function Calling использует общие контекстные инструменты Pipecat: `get_call_context` возвращает снимок данных, полученный существующим backend-резолвером плана. После обновления стабилизации модель сохраняет факты через `remember_call_fact` и запрашивает завершение через `prepare_end_call`; внутренний `end_call` управляется транспортом, а не дополнительной генерацией модели. Новые CRM-записи и изменения бизнес-данных этот эксперимент не выполняет. Подробности — [PIPECAT-STABILITY.md](PIPECAT-STABILITY.md).

## Запуск

### Локально в Docker с backend на хосте

```sh
npm run pipecat:up
npm run pipecat:status
npm run pipecat:logs
```

`compose.pipecat.yaml` собирает отдельный Python 3.12 образ с зависимостями из `uv.lock`, публикует порт **только** `127.0.0.1:8093`, проверяет авторизованный `/health` и использует `restart: unless-stopped`. Backend остаётся обычным Node-процессом. `pipecat:up` добавляет URL и случайный общий токен в корневой `.env`, не печатая секрет и не меняя существующие значения. После первого добавления настроек нужно перезапустить backend. Контейнер получает только ключи и настройки, необходимые прототипу; `.env` не попадает в build context или образ.

Если SOCKS-прокси работает на `localhost` хоста, команда автоматически добавляет отдельный `PIPECAT_ELEVENLABS_PROXY_URL` с `host.docker.internal`; основной `ELEVENLABS_PROXY_URL` для Node не меняется. Произвольный адрес прокси контейнера можно указать этой же переменной. Метрики сохраняются в named volume `pipecat_logs`. Контейнер работает без root с read-only корневой файловой системой. Сервис использует один worker для общей карты сессий.

Если Docker не скачивает зависимости напрямую, `PIPECAT_BUILD_PROXY_URL=http://host.docker.internal:10820` передаёт HTTP-прокси только команде сборки (порт должен соответствовать вашему HTTP-прокси). Эта настройка не меняет глобальный Docker proxy и не применяется к провайдерам работающего сервиса.

Локальный запуск фактически выполнен 12 ноября 2026: контейнер `salesboost-pipecat-pipecat-1` имеет статус `healthy`, backend на хосте получил HTTP 200 через `/api/admin/realtime-test/pipecat/health`. Все 24 Python-проверки прошли внутри Linux-контейнера. Подтверждены UID 10001, отсутствие `/app/.env` в образе, read-only `/app` и доступный для записи `/data/logs`. Корневой `.env` настроен, локальный watcher backend перечитал его. Это подтверждает локальное подключение; публичный endpoint для Voximplant этим запуском не создаётся.

Живая проверка из контейнера тоже прошла: ElevenLabs v4 Turbo через SOCKS5 и `ElevenLabsDialogueTTSService` выдал 128000 байт PCM16 mono 16 кГц; первое аудио прямого TTD-запроса — 376,27 мс, через Pipecat с запуском и подключением — 1839,07 мс. Одна предыдущая попытка дала таймаут; независимые HTTP/WebSocket-проверки и повтор полного TTS-пробника успешны. Результат сохранён в volume (`/data/logs/docker-startup-probe.json`) и `PIPECAT-HYPOTHESIS-PROBES.json`. Телефонные звонки не выполнялись.

Для остановки: `npm run pipecat:down` (volume сохраняется). Для проверки API внутри контейнера без звонков:

```sh
docker compose -f compose.pipecat.yaml exec -T pipecat python probe.py --tts-only --tts eleven_v4_turbo --pipecat-tts
```

В контейнере env передаётся Compose; probe использует `--voice`, иначе читает текущий голос по `ELEVENLABS_AGENT_ID` из корневого `.env`.

### Оба сервиса в Docker — для будущего production-развёртывания

Подготовлен отдельный opt-in overlay:

```sh
docker compose -f compose.prod.yaml -f compose.pipecat.prod.yaml up -d --build
```

Он задаёт backend URL `http://pipecat:8093`, ждёт healthcheck Pipecat и убирает публикацию его порта на хосте. Существующий `compose.prod.yaml` не меняется; overlay не включается автоматически. Публичный HTTPS/WSS endpoint использует существующий reverse proxy backend: путь `/pipecat` должен проходить к приложению с поддержкой WebSocket Upgrade. Тестовое правило Voximplant устанавливается отдельно командой `npm run pipecat:deploy-scenario`.

### Альтернативный запуск Python без Docker

1. Установить `uv` и Python 3.12. В `apps/pipecat-hypothesis` выполнить `uv sync --locked`.
2. Создать локальный `.env` по `.env.example` в этой директории. Указать отдельный длинный `PIPECAT_HYPOTHESIS_TOKEN`, ключи провайдеров, Voximplant и публичный HTTPS URL **отдельного сервиса**. Для Gemini нужен `GEMINI_API_KEY`; существующий OpenAI-ключ не заменяет его. Сохранить `ELEVENLABS_PROXY_URL`, если основной backend использует этот прокси.
3. Установить в Voximplant **новый** сценарий `voice_pipecat_hypothesis` из `voximplant/scenario_voice_pipecat_hypothesis.js` и правило `voice_pipecat_hypothesis_rule`. Не менять существующие правила. `StartScenarios` вызывается только по кнопке тестового звонка.
4. Запустить сервис:

   ```sh
   cd apps/pipecat-hypothesis
   uv run --locked uvicorn service:app --host 127.0.0.1 --port 8093 --no-access-log
   ```

   Направить отдельный HTTPS/WSS tunnel или reverse proxy на этот порт. Сервису нужен один worker: сессии и секреты WebSocket хранятся в его памяти. `--no-access-log` исключает логирование per-call URL с токенами.

5. В окружении основного Node backend указать `PIPECAT_HYPOTHESIS_URL=http://127.0.0.1:8093` и тот же `PIPECAT_HYPOTHESIS_TOKEN`, перезапустить backend. Сам Python-сервис в production compose не добавлен.
6. В `/testing` выбрать план, LLM, версию ElevenLabs и нажать «Проверить API и голос». Проверка синтезирует короткую фразу без звонка. Затем ввести согласованный тестовый номер и нажать «Позвонить через Pipecat». Каждый звонок повторно проверяет доступ/настройки API и голос до набора номера.

API Node находится под существующим `requireTestingSuperadmin`. Python HTTP использует отдельный bearer token, медиа и lifecycle callbacks — краткоживущие per-call токены; повторное подключение к уже использованному WebSocket отклоняется. Production webhook/finalizer и `startVoiceCall` не вызываются.

### Публичное подключение через существующий backend

`PIPECAT_HYPOTHESIS_PUBLIC_URL` — публичная HTTPS-база для адресов, которые Python отдаёт Voximplant. Локальный `http://127.0.0.1:8093` нужен только backend и не доступен облачной телефонии.

Сейчас в корневом `.env` настроено `PIPECAT_HYPOTHESIS_PUBLIC_URL=https://test.eventstream.space/pipecat`. `pipecat:up` автоматически формирует такой адрес из `PUBLIC_BASE_URL` / `VOICE_DIALOG_BASE_URL`, если публичный адрес Pipecat ещё не задан. Backend передаёт `/pipecat/media/<id>` как WebSocket-поток в контейнер и `/pipecat/events/<id>` как lifecycle callback. Эти маршруты принимают только UUID и одноразовый per-call token; Python дополнительно проверяет сессию. Административные endpoints контейнера наружу не проксируются. Публичный `/pipecat/health` возвращает только `ok`, без настроек или ключей.

Проверка без звонка: `npm run pipecat:check-transport`. Она создаёт авторизованный одноразовый transport probe на 30 секунд, подключается по публичному WSS и проверяет передачу PCM-пакета туда и обратно. После проверки nonce удаляется. Проба не создаёт телефонную сессию и не обращается к AI-провайдерам. Финальная проверка прошла: HTTPS 200, WebSocket Upgrade и PCM round-trip подтверждены.

Отдельные `voice_pipecat_hypothesis` и `voice_pipecat_hypothesis_rule` развёрнуты и проверены 12 ноября 2026: scenario ID `3788384`, rule ID `9686731`; SHA256 сценария `76653e9dab5f24f8786345f35d1e0627a1afafc673ae08e8f6c66349f525a009`. Правило имеет специальный outbound pattern, действующие production-сценарии и правила не менялись. Команда `npm run pipecat:deploy-scenario` воспроизводит развёртывание.

В этом окружении прямое обращение к API Voximplant не проходило, а через HTTP-прокси прошло. Для Pipecat задан отдельный `PIPECAT_VOX_PROXY_URL=http://host.docker.internal:10820`, для CLI-развёртывания — `PIPECAT_DEPLOY_PROXY_URL=http://127.0.0.1:10820`. Это не меняет production-маршрутизацию звонков. На другом хосте эти настройки нужно адаптировать или убрать, если прямой доступ работает.

### Gemini 3.8 Flash через ProxyAPI

В `/testing` добавлен отдельный выбор **«Gemini 3.8 Flash · ProxyAPI»** (`gemini_proxyapi`). Ключ берётся из существующего `PROXYAPI_API_KEY`, передаётся контейнеру Compose и используется только для этого маршрута. Прямой Google-вариант сохраняет собственный `GEMINI_API_KEY`; автоматического переключения между ключами, провайдерами или моделями нет. Production-пайплайн не изменён.

Используется тот же `GoogleLLMService` Pipecat и официальный Google SDK с `HttpOptions(base_url="https://api.proxyapi.ru", api_version="v1beta")`, модель строго `gemini-3.8-flash`, thinking `low`. Это [Google-native формат ProxyAPI](https://proxyapi.ru/docs/gemini-api): SDK сам добавляет `/v1beta/models/…`, потоковый ответ использует `streamGenerateContent`. Модель и текстовый ответ проверены живыми запросами. На старом endpoint получение одной модели по ID вернуло 404 при наличии модели в списке и успешной генерации, поэтому preflight этого маршрута проверяет настоящий короткий ответ модели, а не делает вывод о доступности по metadata endpoint.

STT и LLM используют один и тот же маршрут ProxyAPI. Сохраняется двухпроходная обработка завершённых реплик, а не Live API: WAV PCM16 mono 16 кГц → расшифровка Gemini → потоковый текст/Function Calling Gemini → выбранный ElevenLabs. Отдельная озвучка Gemini не используется. Перед звонком preflight проверяет реальные текстовый ответ Gemini и синтез выбранным голосом.

Полная проверка без звонка:

```sh
docker compose -f compose.pipecat.yaml exec -T -e LOGURU_LEVEL=ERROR pipecat python probe_gemini.py --output /data/logs/gemini-proxyapi-probe.json
```

Пробник создаёт или использует синтетическую аудиофразу, распознаёт её **тем же** сервисом Gemini, проводит реальный streaming/Function Calling цикл через Pipecat с инструментом только для чтения, затем передаёт ответ в реальный ElevenLabs Dialogue TTS. Тестовый инструмент не изменяет CRM и не набирает номер.

12 ноября 2026 проверка прошла локально и в Linux-контейнере. В Docker: аудио точно распознано как «Здравствуйте. Проверяем качество голоса и задержку ответа.» за **3382,13 мс**; инструмент вызван, первый текст с учётом этого цикла — **5615,01 мс**; финальный текст «Проверка пройдена. Спасибо, до свидания.» озвучен в PCM16 mono 16 кГц, 94720 байт, первое аудио TTS с запуском сервиса — **2016,02 мс**. Это разовая синтетическая проба с холодными подключениями и дополнительным Function Calling; не p50/p95 и не задержка телефонного звонка. Два прохода Gemini нужно сравнивать с Realtime на реальном разговоре.

Прошли 29 Python-тестов в контейнере, 27 TypeScript-тестов, `tsc` и frontend build. Обновлённый frontend с `gemini_proxyapi` проверен через публичный `/testing` bundle. Полный результат пробы — `docs/PIPECAT-GEMINI-PROXYAPI-PROBE.json`. Для звонка выберите новый вариант, голосовой движок и тестовый номер в гипотезе 3.

`probe.py` использует заданный `ELEVENLABS_VOICE_ID` / `--voice`, иначе читает текущий голос ElevenLabs Agent. Ключи и URL с секретами не включаются в JSON-результат. Ни одна CLI-проба не набирает телефонный номер.

Метрики пишутся в отдельные JSONL (`storage/pipecat-hypothesis/<id>.jsonl`) и выводятся в карточке: STT от конца речи, время решения Smart Turn, первый текст и полная генерация LLM, первое аудио/генерация TTS, отправка → начало воспроизведения и конец речи → начало воспроизведения. Недоступные интервалы имеют `null`, а не ноль. Телефонные события измеряются по времени получения callback сервисом, включая сетевую доставку; это не измерение слышимости на устройстве абонента.

Матрица: OpenAI/Gemini × v3/v4/v4 Turbo × обычный ответ, `угу/ага`, короткое содержательное перебивание, длительное перебивание, пауза внутри фразы, завершение после прощания. Для сравнения закрепить один план, профиль и voice ID (backend может случайно выбирать профиль плана), одинаковые фразы, сеть и повторить каждую ячейку. Единичный API-пробник не доказывает преимущество по p50/p95 или качеству телефонной речи.

## Диагностика звонка по ID

В гипотезе 3 на `/testing` блок «Журнал и история звонков» показывает ID `pc-<UUID>`. Кнопки копируют ID, ссылку на журнал и скачивают полный JSON. ID можно прислать для разбора. Журнал открывается по ID после обновления страницы и перезапуска контейнера; ссылка требует обычного входа суперадминистратора. В списке видны последние 30 запусков, более старые открываются по ID. Полный список событий доступен без прежнего фильтра; строка поиска фильтрует только отображение.

Сохраняются:

- Полные распознанные реплики клиента, частичный и окончательный текст агента, статусы отмены, UTC-время и время от начала звонка, последовательные номера событий.
- VAD и Smart Turn, длительность речи, решение об окончании реплики, короткие реакции, подтверждённые перебивания и запросы очистки очередей.
- Исходный бизнес-промпт и эффективные настройки Realtime. Для каждого `response.create`: request ID, turn, причина, последний аудиокоммит, ожидающие расшифровки, локальный контекст и зеркало полученных conversation items провайдера. Ответы связаны с request ID, response ID и item ID; удаления из контекста содержат удалённый item. Это зеркало событий клиента, а не чтение внутреннего состояния модели.
- Промежуточная и финальная STT, Function Calling и результаты, ошибки, включая ошибки конкурентных запросов, которые Pipecat иначе только пишет в debug.
- Задержки STT, LLM, TTS, отправки и воспроизведения, TTS-контексты и метрики Pipecat. Voximplant callbacks связаны с сегментами аудио: отправка, старт, окончание, очистка, устаревшие подтверждения. Аудиопоток агрегируется по секундам: объём, длительность PCM, интервалы и peak. Сырые PCM/base64 в диагностический JSON не пишутся.

Для анализа ответа после паузы `reply_reference` фиксирует предыдущий ответ агента, недавние вопросы по знаку `?`, последний подтверждённый телефонией сегмент и паузу от его окончания до начала речи клиента. Это хронологическая подсказка, не семантическая классификация. Подтверждение Voximplant доказывает окончание конкретного сегмента; оно не доказывает, что весь сгенерированный ответ был услышан. Связь сегмента с ответом берётся из активного response ID при его создании. `tts_word_delivered` отражает локальное время выдачи текста TTS и не заменяет телефонное подтверждение. Сопоставлять нужно генерацию, отмены, очередь, callbacks и контекст запроса вместе.

Архив — `/data/logs/<UUID>.jsonl` и `<UUID>.meta.json` в существующем Docker volume. Ограничение в 1000 событий применяется только к памяти процесса, экспорт читает весь файл. Ключи API, transport tokens и секреты в URL удаляются перед записью. Архив содержит текст разговора, бизнес-контекст и промпт; административные endpoints доступны только через существующий доступ к `/testing`, публичный gateway их не открывает. Автоматического удаления архивов пока нет.

Для получения журнала в рабочем каталоге:

```bash
npm run pipecat:diagnose -- --id pc-<UUID>
```

Команда сохраняет полный JSON в `storage/pipecat-diagnostics/` с правами `0600` и выводит сводку задержек, ошибок и удалений контекста. `GET /sessions/<id>/diagnostics?after=<seq>&limit=500` возвращает события постранично; `export` возвращает весь архив. Оба endpoint требуют отдельного service token, в браузер он не передаётся.

Старые JSONL доступны с пометкой `legacy`: отсутствующие текст агента и снимки контекста задним числом восстановить нельзя. Активная сессия прошлого процесса после перезапуска обозначается `interrupted`, архив остаётся доступным.

12 ноября 2026 Realtime-вариант гипотезы переключён на входную транскрипцию `gpt-live-transcribe`, `languages=["ru"]`, без явного delay. Ревизия сервиса `pipecat-live-stt-1`; основной диалог остаётся на `gpt-realtime-2.1`. Настройка применяется к новым звонкам Pipecat-гипотезы. Частичные результаты пишутся в `stt_partial`, окончательные — в `stt_completed`; частичный текст не подтверждает перебивание и не заменяет финальную проверку коротких реакций. Silero/Smart Turn по-прежнему управляют границами реплик, server VAD выключен.

В ревизии `pipecat-mini-1` добавлен отдельный выбор «OpenAI Realtime 2.1 Mini» (`provider=openai_mini`, модель `gpt-realtime-2.1-mini`). Обычная 2.1 остаётся отдельным вариантом. Обе модели используют один GatedRealtime-пайплайн: Silero/Smart Turn, live-транскрипцию ru, native TTS выключен, ElevenLabs, защиту коротких реакций, отмену очереди, память и ожидание подтверждения окончания прощания. Preflight проверяет точное имя выбранной Realtime-модели; скрытой замены на полную 2.1 нет. Имя модели сохраняется в истории и диагностике. Reasoning low по умолчанию, minimal доступен как эксперимент. Очистка накопленной тишины по умолчанию выключена.

Проверка Mini: 61 Python-тест, включая сборку реального графа для обоих Realtime-вариантов и проверку text-only/VAD-off/live STT; 31 тест Node-маршрутов/шлюза, tsc и frontend build. Контейнер обновлён и healthy; полный API preflight для Mini + ElevenLabs v4 turbo прошёл, включая получение PCM, `/data/logs/mini-readiness-20261112.json`. Два текстовых синтетических сценария (`pcr-7b8cb3b0-da55-4738-a519-06a4974fd547`) завершились без transportErrors и отказов закрытия; в callback корректно сохранено «завтра после десяти утра» и запрошено завершение. Семантическая оценка имеет статус review: introduction повторяет представление и задаёт два вопроса в одной реплике, поэтому качество реального диалога отдельно проверяется звонком. Телефония и VAD этими текстовыми сценариями не измерялись. Звонки для проверки не выполнялись.

После ошибки пользователя `Preflight failed (InvalidStatus)` добавлена диагностика preflight (`pipecat-live-stt-2`). Ошибка WebSocket теперь называет провайдера и HTTP-код. Однократно повторяется только отклонённый handshake с 429/500/502/503/504; генерация TTS после подключения автоматически не повторяется. Каждая проверка получает `pf-UUID`, результат сохраняется в `/data/logs/pf-UUID.json` (0600) и `preflight_result` в stdout: провайдер, TTS-модель, длительность, статус и безопасная причина ошибки. Тело ответа провайдера, ключи и адрес прокси с реквизитами не сохраняются. При запуске Docker значения корневого `.env` имеют приоритет над одноимёнными переменными оболочки.

При отключении прокси обнаружена оставшаяся автоматически добавленная запись `PIPECAT_ELEVENLABS_PROXY_URL`: одного комментирования `ELEVENLABS_PROXY_URL` было недостаточно. Запись Docker-прокси также отключена. `configure-pipecat-docker.mjs` больше не сохраняет производный прокси в `.env`; `pipecat-env.mjs` вычисляет отображение localhost → host.docker.internal при запуске, используя актуальный основной параметр. Если оба параметра отсутствуют, унаследованные значения прокси из оболочки не подхватываются. Явный `PIPECAT_ELEVENLABS_PROXY_URL` по-прежнему имеет приоритет; пустое значение отключает прокси только для Pipecat даже при наличии основного прокси. Пять Node-тестов покрывают удаление параметров, изменение локального порта, пустое переопределение и отдельный Docker-прокси. После обновления контейнера `elevenlabs_proxy()` возвращает None. Полный preflight напрямую прошёл для ElevenLabs v3, v4 и v4 turbo: OpenAI подтвердил live-транскрипцию/ru, text-only и отключённый server VAD; ElevenLabs вернул PCM16 mono 16 кГц для каждого варианта. Результат: `/data/logs/preflight-no-proxy-20261112.json`. Телефонные звонки не выполнялись.

Исходный HTTP-код ошибки `InvalidStatus` восстановить нельзя: предыдущий обработчик его не сохранял. Повторная проверка подтвердила рабочий OpenAI Realtime с live-транскрипцией и проблему сети ElevenLabs: текущий SOCKS5 на `localhost:11080` работает с хоста, а TCP из контейнера к `host.docker.internal:11080` отклоняется (IPv4 ECONNREFUSED). Автоматический перенос имени localhost в host.docker.internal сам по себе не открывает порт прокси для Docker. Для звонка с включённым прокси нужен доступный контейнеру SOCKS5: прямой адрес сервера в `PIPECAT_ELEVENLABS_PROXY_URL` либо корректно опубликованный локальный прокси. Временная проверка существующего HTTP-прокси сборки не прошла; как маршрут ElevenLabs он не включён. Исправление диагностики не означает успешного прохождения полного preflight: его нужно повторить после восстановления доступности прокси.

Для последующего анализа архив сохраняет `transcriptionModel` в метаданных и конфигурации, запрошенную транскрипцию в `pipeline_configuration` и полную подтверждённую провайдером конфигурацию в `provider_session_confirmed`. После пересборки контейнер healthy; проверка API из контейнера подтвердила live-модель с русским языком, text-only output и VAD-off, а также доступ к ElevenLabs-голосу. Результат `/data/logs/live-stt-readiness-20261112.json`, без телефонного звонка. Все 56 Python-тестов прошли, включая сериализацию правильного поля `languages` и сохранение имени STT-модели. Результаты предварительных 15 замеров — в `docs/PIPECAT-REALTIME-STT-BENCHMARK.md`.

Проверка 12 ноября 2026: 34 Python-теста (включая архив свыше 1000 событий, перезапуск, пагинацию, секреты и передачу неизменённых событий API), 32 TypeScript-теста, `tsc` и frontend build. `probe_diagnostics.py` открыл реальную сессию `gpt-realtime-2.1`, получил вопрос, выдержал 4 секунды и отправил синтетическое аудио. Записаны два ответа, STT и контекст второго запроса: журнал `pc-6103672d-b62c-4e91-a738-c7cf10ca3fce`. Телефон и TTS в этой пробе не использовались. Через работающий backend проверены экспорт нового журнала, открытие старого и отказ неавторизованному запросу. Диагностика не меняет стратегию диалога и сама по себе не исправляет семантическую ошибку после паузы.
