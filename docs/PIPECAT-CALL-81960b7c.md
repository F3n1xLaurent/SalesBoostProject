# Звонок 81960b7c · длинные паузы и следующий шаг

Исходный runtime: semantic-14. Анализ событий, подтверждений воспроизведения и текста; запись не прослушивалась.

## Задержки

| Этап | Медиана исходного звонка |
| --- | ---: |
| Silero + Smart Turn | 268 мс |
| STT | 972 мс |
| Смысловое решение | 1259 мс |
| Отправка → начало воспроизведения | 282 мс |
| Конец речи → начало ответа | 2511 мс |

Это выборки разных событий, не арифметическое разложение каждого ответа. Первая реплика началась примерно через 1,45 с после окончания речи сотрудника. Самый долгий первый ответ занимал около 5,88 с (внутри прозвучала подготовленная «Секунду»). Значение 17,6 с относится к следующей реплике того же turn после уже воспроизведённого длинного ответа; его нельзя считать непрерывной тишиной или одной генерацией.

Главные провалы были логическими:

- На «можно завтра» ещё не было часа. Общий вопрос о визите уже зарезервировал ID обоих полей — дня и времени. Поэтому уточнение часа блокировалось как дубль, звучало «По времени пока не определились», затем контроллер молчал.
- Предложение сотрудника самому перезвонить после проверки доступности не распозналось как следующий шаг. Контроллер продолжал обсуждать визит и не отвечал на ряд подтверждений.
- При встречном вопросе и условии визита сначала генерировался ответ, затем после полного playback ACK запускалась ещё одна генерация уточнения. Повторяющееся уточнение мог отсеять фильтр, оставив отсутствие аудио.
- В одном запросе смыслового API была HTTP-ошибка. Её статус в старом журнале не сохранён; достоверно приписать ошибку сети или конкретному коду HTTP нельзя.

## Изменения semantic-15

- В semantic-режиме общий вопрос о визите и узкие уточнения дня/часа имеют разные ID. После ответа только о дне разрешено одно уточнение времени. Повтор узкого уточнения по-прежнему блокируется; общий вопрос после уже заданного узкого также не обходит запрет. Старый контроллер сохраняет прежнее поведение.
- Разбор callback учитывает оба направления: просьбу перезвонить и предложение сотрудника самому связаться позже. Независимая проверка разрешения завершить разговор сохраняется. Завершение подтверждает последующую связь, не выдумывает запись на визит, ждёт телефонного playback ACK.
- Нерешённое условие наличия отделено от безусловного предложения визита: один только названный день не устраняет условие.
- Встречный вопрос и уточнение условия обрабатываются одним запросом Realtime: ответ плюс максимум один новый вопрос. Вторая автоматическая генерация clarify_visit после воспроизведения больше не запускается. Сохраняются ограничения легенды, фактов, времени и повторов.
- Ошибки смыслового API теперь сохраняют HTTP-статус, если он доступен.

Эти изменения убирают обнаруженные зависания и лишнюю генерацию. Они не являются замером новой медианы живого звонка и не обещают устранить базовые ~2,5 с текущей последовательной цепочки STT → понимание → воспроизведение.

## Проверки

428 Python-тестов прошли. Новые проверки: общий вопрос не блокирует один недостающий час, повтор уточнения блокируется; встречный вопрос и условие требуют одну генерацию; callback даёт озвученное подтверждение с завершением после ACK. Дополнительно используются синтетические диалоги через настоящие Realtime/Decisions/ElevenLabs с имитацией телефонных ACK, без PSTN.
