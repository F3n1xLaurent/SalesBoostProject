# pc-270d2b7c-7539-4302-bd99-7cc9338daed9 и controller-2.2

13 ноября 2026. Реальный звонок на controller-2.1, полная `gpt-realtime-2.1`, ElevenLabs v4 Turbo. Все обязательные темы пройдены. Каждый из пяти обязательных вопросов задан один раз. День и время визита сохранены после «угу», разговор завершён по `hangup_after_playback`. Ошибок STT/соединения и таймаута распознавания нет.

## Backchannel в этом звонке

Флажок включён, но ни одной реакции не было поставлено в очередь. Все ответы — готовые клипы, без свободной LLM-генерации, поэтому сценарий «Так…» при ожидании генерации не запускался. Единственная SmartTurn INCOMPLETE возникла на ходе 9, когда уже обсуждался визит. Для визита короткие реакции отключены, чтобы их не путали с подтверждением договорённости. В остальных ходах SmartTurn определил завершённые реплики.

Таким образом, отсутствие backchannel соответствует текущей политике и не означает неработоспособность проигрывателя. Оно также не доказывает, что разговор воспринимался достаточно естественно. Принудительная вставка отдельной реакции перед каждым готовым вопросом не добавлена. В controller-2.2 появляются `backchannel_opportunity` и причины `backchannel_skipped`: длительность речи, визит/приветствие, просьба подождать, активный выход, лимит частоты, продолжающаяся речь, смена состояния. Это позволяет отличить отсутствие подходящего момента от пропущенного воспроизведения.

Медиана `speech_to_playback_ms` по десяти ответам — 1,50 с, диапазон 1,16–4,58 с. Это время до подтверждения начала телефонного воспроизведения; оно включает доставку callback. Turn detection — медиана 269 мс, STT — 1088 мс. Более длинные ответы по визиту включали подготовку ещё не сохранённой озвучки конкретного времени. Эти медианы относятся к прежним формулировкам controller-2.1, не являются замером новой версии.

## Запрошенные изменения

В controller-2.2 приветствие: **«Здравствуйте! Звоню по объявлению, машина ещё продаётся?»**. Имя отсутствует. Представление остаётся по запросу менеджера. Native fallback получает то же правило, а фильтр не выпускает незапрошенное представление; при фильтрации история провайдера ремонтируется существующим механизмом.

Для известных формулировок демонстрационного плана заранее готовится разговорная озвучка:

| Было | Стало |
| --- | --- |
| Актуальный ли пробег в объявлении? | Скажите, пробег в объявлении актуальный? |
| Что по порогам, не сильно ли гнилые? | А как пороги по состоянию, коррозия есть? |
| Были ли ДТП? | Подскажите, пожалуйста, были ли у машины ДТП? |
| Можете ли сделать скидку? | А по цене можно будет немного поторговаться? |
| Сколько владел автомобилем последний владелец? | А последний владелец как долго на ней ездил? |

Смысл темы и идентификаторы не меняются. Индивидуальный вопрос, содержащий особые условия, цену или конкретную деталь, не заменяется общей формулировкой по совпадению ключевого слова. Для неизвестных формулировок сохраняется весь исходный текст с вежливым вводным обращением; уже вежливые вопросы не получают второй такой префикс. На ответном ходе новый LLM-вызов для изменения формулировки не нужен: изменённые клипы готовятся до набора номера и затем берутся из кеша.

Дополнительно по ходу 9: «Сейчас я посмотрю секундочку» теперь сохраняет уже названный день визита и переводит контроллер в ожидание вместо немедленного уточняющего вопроса. Backchannel при явной просьбе подождать остаётся отключённым.

## Проверки и запуск

159 Python unittest прошли, включая приветствие без имени, представление по запросу, запрет незапрошенного имени в native-тексте, сохранение условий нестандартного вопроса, совместимость разговорного вопроса с темами и кешем, причины пропуска backchannel и ожидание проверки времени визита.

Изолированный Docker обновлён. Новые звонки этого режима маркируются `pipecat-controller-2.2`. Production voice pipeline и выбор полной/Mini модели не переключались. Проверка реальными API — пять вымышленных текстовых сценариев через полную Realtime и ElevenLabs, с имитацией телефонного ACK; она не заменяет следующий реальный звонок и прослушивание новой озвучки.

Итог — **5/5 сценариев прошли все проверки**, включая имя только по запросу, новые формулировки и отсутствие дублей обязательных тем. Отчёт `pctrl-3e57bfad-2fdd-4aab-b483-da29b9c502ee` сохранён в игнорируемом `storage/pipecat-benchmarks/controller-2.2/` с правами 0600. В одном сценарии backchannel намеренно вызывается тестовым hook: это проверка выпуска клипа, не оценка выбора подходящей акустической паузы.
